1.makefile环境搭建

1.1 什么是makefile

Makefile本质上是一个“编译规则文件”。

它告诉计算机：

  • 工程里有哪些源文件要参与编译
  • 每个源文件用什么编译器去编译
  • 头文件路径在哪里
  • 宏定义有哪些
  • 最后怎样把很多个目标文件链接成 elf、hex、bin 文件

简单来说，Makefile 就像一个“自动化编译说明书”。

在 STM32 工程里，如果不用 IDE 手动点“Build”，那么就可以通过 Makefile 让编译器按我们写好的规则自动完成整个构建过程。

例如一个 STM32 工程通常会经历下面几个步骤：
1.预处理：把 main.c、gpio.c、usart.c 等源文件处理成 .i 文件

  • 展开 #include
  • 替换 #define
  • 处理条件编译
    2.编译：把 .i 文件编译成汇编文件 .s
    3.汇编：把 .s 文件汇编成目标文件 .o
    4.启动文件处理：启动文件本身一般也是 .s，直接经过汇编生成 .o
    5.链接：把所有 .o 文件和链接脚本 .ld 链接生成 .elf
    6.格式转换：把 .elf 转成

这些动作都可以由 Makefile 自动完成。

所以可以把 Makefile 理解为：

  • 对初学者来说：它是“自动编译脚本”
  • 对工程开发来说：它是“项目构建规则”
  • 对团队协作来说：它是“统一编译方式”

Makefile语法规则：
Makefile 是工程自动化构建中非常常见的工具文件，它主要用于描述：
某个目标文件依赖哪些源文件，以及应该执行什么命令来生成这个目标。

在 STM32、Linux 驱动、嵌入式交叉编译等项目中，Makefile 都非常常用。
通过编写 Makefile，可以让我们使用一条 make 命令，自动完成编译、汇编、链接、格式转换等一系列操作。

12.Makefile 的核心思想总结
学习 Makefile 时，最重要的是先理解它不是“脚本语言”，而是“规则描述文件”。

它的核心思想是：

  • 描述目标和依赖关系
  • 只有依赖变化时才重新生成目标
  • 通过规则把多个构建步骤自动串起来

所以你可以把 Makefile 理解成一句话：
“我要生成什么，它依赖什么，我该用什么命令生成它。”

1.2 为什么使用Makefile而不是MDK

在 STM32 开发中，MDK 是非常常见的开发工具，界面友好，上手方便，适合初学者快速入门。
但是在实际项目中，尤其是双核工程、自动化构建、跨平台开发场景下，Makefile 往往更灵活、更稳定。
这次项目里选择 Makefile，一个很重要的原因就是：
CubeMX 生成的 MDK 双核工程容易出现 CM4 和 CM7 工程互相包含源码的问题，导致编译失败。

例如：

  • CM4 工程错误地编译了 CM7 的 gpio.c
  • CM4 工程去包含 CM7 的 gpio.h
  • 最终出现头文件找不到、源文件混编、链接异常等问题

也就是说，问题不是 STM32 代码本身有错，而是 CubeMX 生成的 MDK 工程配置在双核场景下容易混乱。
相比之下，使用 Makefile 有几个明显优点：

1.编译规则完全可控
我们可以明确规定：

  • CM4 只编译 CM4/Core/Src
  • CM7 只编译 CM7/Core/Src
    不会出现 IDE 自动生成时“多带了不该带的文件”。

2.更适合双核工程管理
双核工程最怕“工程配置互相污染”。
Makefile 可以把 CM4 和 CM7 分开写，逻辑清晰，维护简单。

3.不依赖图形界面
只要装好 arm-none-eabi-gcc 和 make，在命令行输入一条命令就能编译。
对自动化构建、批量构建、服务器构建特别方便。

4.更容易和 VS Code 配合
现在很多嵌入式开发已经不局限于 MDK，Makefile + GCC + VS Code 是一种很常见的方案。

5.便于理解编译原理
学习 Makefile 的过程，也是在学习：

  • 编译器怎么工作
  • 链接脚本有什么作用
  • elf/hex/bin 是怎么来的

所以这里不用 MDK，不是说 MDK 不好，而是因为：
在这个双核 STM32H7 工程中，CubeMX 生成的 MDK 工程会互相包含，导致编译失败；而 Makefile 可以更精确地控制每个核各自的编译内容。

1.5 makefile中的.mk文件

.mk 是什么
.mk 就是 Makefile 片段：只定义变量（源文件列表、头文件路径等），不单独执行 make。
主 Makefile 用 include xxx.mk 把它“拼”进来，相当于把一大段变量写进当前 make 进程。

和 C 里 #include "module.h" 类似：主文件管流程，.mk 管这个模块要编译哪些 .c、加哪些 -I。

为什么要拆成 .mk
STM32 的 Makefile 常由 STM32CubeMX / projectgenerator 生成，一改 IOC 再生成，主 Makefile 容易被覆盖。

把 LVGL、Modbus、日志、触摸等手写/第三方 内容放到独立 .mk 里：

  • Cube 重生主 Makefile 时，只需保留几行 include xxx.mk 和 $(XXX_SOURCES)
  • 各模块源文件列表集中维护，主 Makefile 不会膨胀到上千行
  • 关掉某功能时，注释一行 include 或从 C_SOURCES 里去掉对应 $(XXX_SOURCES) 即可

.mk 文件头注释里写的 keep this file when regenerating Makefile from CubeMX，就是这个用意。

.mk 里通常定义什么
每个模块 .mk 一般成对定义两个变量：

变量后缀 含义 用法
XXX_SOURCES 要参与链接的.c路径列表 展开进主C_SOURCES
XXX_INCLUDES 头文件搜索路径 展开进主C_INCLUDES

路径相对执行make的目录（一般是 Makefile/CM7/），所以常见写法是

2.STM32H747双核单片机介绍

STM32H747 是 STMicroelectronics 推出的高性能双核微控制器，属于 STM32H7 系列。该器件内部集成两个 ARM Cortex 内核：

  • Cortex-M7：高性能主核
  • Cortex-M4：实时控制辅核
  • 双核架构的意义
    传统单核 MCU 中，所有任务都运行在同一个处理器上。随着系统复杂度提升，常见问题包括：
  • 图形界面、通信协议、存储管理占用大量 CPU
  • 实时采样与控制任务容易受阻塞
  • 中断、任务调度、时序控制相互干扰
  • 软件架构逐渐臃肿，维护和调试难度升高

STM32H747 的双核架构正是为解决这些问题而设计。其核心思想是：

  • M7 负责高性能任务
  • M4 负责确定性实时任务

这种职责拆分可以在同一芯片内部实现“业务处理”和“实时控制”的解耦。

  • 两个内核分别负责什么：
    Cortex-M7 是主核，特点是主频高、运算能力强、适合执行复杂软件栈。
    典型工作内容：
  • 图形界面处理
  • LCD / 触摸屏显示
  • 协议栈运行
  • 文件系统管理
  • 数据运算与分析
  • USB / 网络通信
  • 大规模任务调度

在实际项目中，M7 通常承担“系统主控”的角色。

Cortex-M4 更适合实时性要求高、执行逻辑相对稳定的控制任务。
典型工作内容：

  • 传感器周期采样
  • PWM / 电机控制
  • ADC 数据采集
  • 串口、SPI、I2C 外设服务
  • 实时控制环路
  • 中断驱动型执行任务
    在工程分工上，M4 通常承担“实时协处理器”的角色。

4.1 GPIO

4.1.1 GPIO的概念

  • GPIO 的概念
    GPIO，全称是 General Purpose Input Output，中文一般叫 通用输入输出口。

它是单片机、SoC、FPGA 等芯片上最基础、最常用的一类外设接口，用来让芯片和外部电路发生最直接的交互。
简单理解：

  • Input（输入）：芯片通过 GPIO 读取外部引脚上的电平状态
  • Output（输出）：芯片通过 GPIO 控制引脚输出高电平或低电平

所以，GPIO 本质上就是芯片与外部世界沟通的一扇“门”。
比如按键、LED、蜂鸣器、继电器、传感器的数字信号，很多都是先通过 GPIO 来连接和控制的。

  • GPIO 能做什么
    GPIO 最典型的用途有这些：
    1.读取按键状态
    比如用户按下按键后，GPIO 输入电平发生变化，程序就能知道按键是否被按下。

2.控制 LED 亮灭
程序让某个 GPIO 输出高电平或低电平，就可以点亮或熄灭 LED。

3.驱动简单外设
比如蜂鸣器、三极管、继电器模块等，很多都可以直接或间接通过 GPIO 控制。

4.检测外部数字信号
比如某个模块输出 0/1 状态，MCU 可以通过 GPIO 读取。

5.复用为其他外设功能引脚
很多芯片里的引脚不只是普通 GPIO，还可以复用成 UART、SPI、I2C、PWM、CAN 等功能。

  • GPIO 的核心作用
    GPIO 虽然看起来简单，但它的重要性非常高，因为它承担了两个最基础的任务：
  • 把外部信号送进芯片
  • 把芯片的控制意图送到外部电路

如果把单片机比作“大脑”，那么 GPIO 就像大脑和手脚、感觉器官之间的神经接口。
没有 GPIO，程序再复杂，也很难真正控制硬件。

4.1.2 GPIO的工作模式

GPIO 的工作模式，指的是单片机对某个引脚内部电路连接方式的配置。不同的工作模式决定了该引脚是用于输入信号、输出信号，还是作为片上外设的功能引脚使用。

在 STM32 中，GPIO 常见可归纳为 8 种工作模式。

  • 1.浮空输入模式
    浮空输入模式下，引脚作为输入端使用，单片机只负责读取引脚上的电平状态，不对该引脚内部连接上拉电阻或下拉电阻。

也就是说，当外部电路给这个引脚输入高电平或低电平时，单片机可以正常读取；但如果外部没有接信号，这个引脚就处于悬空状态，电平可能不稳定，容易受到干扰。

特点：

  • 只能输入，不能输出
  • 内部没有上拉或下拉
  • 外部必须提供明确电平
  • 悬空时电平不确定

常见应用：

  • 外部已有稳定驱动信号的数字输入
  • 某些传感器数字输出信号输入
  • 2.上拉输入模式
    上拉输入模式下，引脚作为输入端使用，同时内部接入一个上拉电阻，将引脚默认拉到高电平。

如果外部电路没有对引脚施加信号，那么单片机读取到的通常是高电平；如果外部把引脚拉低，那么单片机就会读取到低电平。

这种模式的作用是避免引脚悬空，使输入状态更加稳定。

特点：

  • 默认状态为高电平
  • 可以防止输入悬空
  • 适合按键等常见输入场景

常见应用：

  • 按键输入
  • 开关量检测
  • 默认需要保持高电平的输入信号

例如，按键一端接 GPIO，另一端接地。当按键未按下时，由于内部上拉作用，引脚保持高电平；按下后引脚被接地，读取为低电平。

  • 3.下拉输入模式
    下拉输入模式下，引脚作为输入端使用，同时内部接入一个下拉电阻，将引脚默认拉到低电平。

如果外部没有输入信号，单片机读取到的是低电平；如果外部给它一个高电平，则可读取到高电平。

这种模式与上拉输入类似，只是默认电平相反。

特点：

  • 默认状态为低电平
  • 防止引脚悬空
  • 适合默认要求低电平的输入场合

常见应用：

  • 默认需要保持低电平的检测信号
  • 某些触发信号输入
  • 4.模拟输入模式
    模拟输入模式主要用于让 GPIO 引脚接收模拟信号，而不是普通的数字高低电平信号。
    在数字输入模式下，引脚只关心“0”或“1”；而在模拟模式下，引脚可以接收连续变化的电压值，供 ADC、DAC 或其他模拟功能模块使用。
    配置为模拟模式后，数字输入输出相关电路通常会被关闭，以减少功耗和数字噪声对模拟信号的干扰。

特点：

  • 用于模拟信号输入或相关模拟功能
  • 不进行数字高低电平判断
  • 有利于降低干扰

常见应用：

  • ADC 采样输入
  • 模拟电压检测
  • 某些低功耗场景
  • 5.推挽输出模式
    推挽输出模式是最常用的 GPIO 输出模式。
    在这种模式下，引脚既可以主动输出高电平，也可以主动输出低电平。

所谓“推挽”，可以理解为引脚内部有两组驱动电路：

  • 一组负责把引脚拉高
  • 一组负责把引脚拉低

因此，输出高低电平都比较有力，驱动能力较强，适合大多数普通数字输出场合。

特点：

  • 能主动输出高电平和低电平
  • 输出状态明确
  • 驱动能力较强
  • 应用最广泛

常见应用：

  • LED 控制
  • 蜂鸣器控制
  • 继电器控制信号
  • 普通数字控制输出

例如，控制 LED 时，GPIO 输出高电平或低电平，就可以直接控制 LED 的亮灭。

  • 6.开漏输出模式
    开漏输出模式下，引脚内部只能主动拉低电平，不能主动输出高电平。
    当需要输出高电平时，引脚实际上处于高阻态，此时必须依靠外部上拉电阻把电平拉高。

因此，开漏输出只有两种状态：

  • 输出低电平：由内部电路主动拉低
  • 输出高电平：内部不驱动，由外部上拉电阻拉高

这种模式最大的特点是便于多个器件共享一条信号线，也适合不同电压系统之间的接口连接。

特点：

  • 只能主动输出低电平
  • 输出高电平需要上拉电阻
  • 可实现“线与”功能
  • 适合总线通信和电平转换

常见应用：

  • I2C 总线
  • 多设备共享信号线
  • 不同电平系统接口

例如，在 I2C 通信中，SCL 和 SDA 通常都采用开漏输出方式，并配合上拉电阻使用。

  • 7.复用推挽输出模式
    复用推挽输出模式下，引脚不再作为普通 GPIO 使用，而是交给片上某个外设模块控制，同时输出方式采用推挽方式。

所谓“复用”，就是一个引脚除了可以作为普通输入输出口，还可以承担串口、SPI、定时器、PWM 等外设功能。当配置成复用模式后，引脚的电平输出不再由普通 GPIO 寄存器直接控制，而是由对应外设控制。

如果该外设需要较强、明确的高低电平输出，一般就使用复用推挽输出模式。

特点：

  • 引脚由片上外设控制
  • 采用推挽输出方式
  • 能主动输出高低电平
  • 适合高速、稳定的数字信号输出

常见应用：

  • USART 发送引脚
  • SPI 时钟和数据输出
  • 定时器 PWM 输出
  • 普通外设数字信号输出
  • 8.复用开漏输出模式
    复用开漏输出模式同样属于外设复用模式，只是它采用的是开漏输出方式。
    也就是说，引脚交由某个片上外设控制，但该外设控制引脚时，只能主动输出低电平，高电平仍然需要外部上拉电阻提供。
    这种模式一般用于那些协议本身要求开漏结构的外设接口。

特点：

  • 引脚由外设控制
  • 采用开漏方式输出
  • 高电平依赖上拉电阻
  • 适合总线型通信

常见应用：

  • I2C 接口引脚
  • 某些特殊总线信号

输入模式用于检测外部信号，输出模式用于控制外部器件，复用模式用于连接片上专用外设，模拟模式用于处理模拟电压信号。 ​
其中，推挽输出适合大多数普通数字输出场景，开漏输出则常用于 I2C 等需要上拉电阻的总线通信。 ​
理解这 8 种模式的区别，是学习 STM32 GPIO 配置和外设接口设计的基础。


4.1.3使用GPIO点亮LED

使用 GPIO 点亮 LED，本质上就是让单片机通过某个 GPIO 引脚输出高电平或低电平，从而控制 LED 的导通与截止。

LED 是发光二极管，具有单向导电特性。只有当电流从 LED 的正极流向负极时，LED 才会点亮；如果电流方向不对，LED 就不会发光。因此，GPIO 控制 LED，实际上控制的是电流是否能够流过 LED。

在单片机电路中，GPIO 引脚可以配置为输出模式。当 GPIO 输出高电平或低电平时，引脚电压会发生变化，这个电压变化会影响 LED 两端是否形成电压差，从而决定是否有电流流过 LED。

GPIO 点亮 LED 常见有两种连接方式。

第一种是 GPIO 输出高电平点亮 LED。

这种连接方式通常是：GPIO 引脚接限流电阻，限流电阻接 LED，再接地。当 GPIO 输出高电平时，引脚输出接近 VCC 的电压，电流从 GPIO 流出，经过限流电阻和 LED，最后流向 GND，LED 被点亮；当 GPIO 输出低电平时，电流无法正常流过，LED 熄灭。

第二种是 GPIO 输出低电平点亮 LED。

这种连接方式通常是：电源 VCC 接限流电阻，限流电阻接 LED，再接 GPIO 引脚。当 GPIO 输出低电平时，GPIO 相当于把回路下端接地，电流从 VCC 流出，经过限流电阻、LED，最后流入 GPIO，LED 点亮；当 GPIO 输出高电平时，LED 两端几乎没有电压差，LED 熄灭。

这种方式也常叫作“低电平点亮”或“灌电流驱动”。

在实际应用中，LED 不能直接接在电源和 GPIO 之间，通常要串联一个限流电阻。因为 LED 导通后内阻很小，如果没有限流电阻，电流可能过大，不仅会烧坏 LED，也可能损坏 GPIO 引脚。限流电阻的作用，就是限制回路中的电流，让 LED 和单片机都能安全工作。

因此，学习“使用 GPIO 点亮 LED”，首先要理解以下几点：

  1. GPIO 必须配置为输出模式
    只有输出模式下，GPIO 才能主动输出高电平或低电平，用来控制 LED。

  2. LED 是否点亮取决于是否有电流流过
    不是单纯看高电平或低电平，而是看 LED 两端是否形成正确的导通电流。

  3. LED 有方向性
    正负极接反时，LED 一般不会点亮。

  4. 必须串联限流电阻
    这是保护 LED 和 GPIO 的基本措施。

  5. 点亮逻辑与接法有关
    有的电路是高电平点亮，有的电路是低电平点亮，编程前必须先看原理图。

总结来说，GPIO 点亮 LED，就是利用 GPIO 输出电平控制电流通断，从而实现 LED 的亮灭。这是学习单片机 GPIO 输出功能最基础、最典型的实验之一。

4.2 中断

  • 1.中断的概念
    中断，是指单片机在执行主程序的过程中，如果发生了某个需要立即处理的事件，CPU 会暂时停止当前程序，转去处理这个事件，处理完成后，再返回原来的位置继续执行。​
    它的核心作用，就是让单片机能够及时响应外部或内部发生的事件，而不需要主程序一直反复查询。

  • 2.为什么需要中断
    如果没有中断，单片机想知道某个事件是否发生，只能不断去检查，这种方式叫轮询。​
    例如检测按键时，主程序需要不停读取按键状态、判断是否按下。这样虽然可以实现功能，但会占用大量 CPU 时间，而且响应速度也不够高。​
    有了中断以后，CPU 平时可以先执行主程序，只有当事件真正发生时，才去处理。 ​
    因此，中断本质上是一种“事件来了再处理”的机制。

  • 3.中断的基本工作过程
    中断的执行过程可以概括为以下几个步骤：​
    1.主程序正常运行 ​
    2.某个中断事件发生 ​
    3.硬件向 CPU 提出中断请求 ​
    4.CPU 暂停当前主程序 ​
    5.进入对应的中断服务函数 ​
    6.处理中断事件 ​
    7.处理完成后返回主程序继续执行​
    所以，中断并不是程序乱跳，而是“先暂停、再处理、再返回”的过程。

  • 4.什么是中断源​
    中断源，就是能够引发中断的事件来源。​
    常见的中断源有：​
    1.外部按键触发 ​
    2.定时器计时到达 ​
    3.串口接收到数据 ​
    4.ADC 转换完成 ​
    5.DMA 传输结束 ​
    6.外部引脚电平变化​
    也就是说，只要某个硬件事件满足条件，就可能产生中断请求，这个事件本身就是中断源。

  • 5.中断服务函数​
    当中断发生后，CPU 会跳转去执行一段专门处理这个事件的程序，这段程序就叫中断服务函数。​
    中断服务函数的作用，就是对当前中断事件进行处理。 ​
    例如：​
    1.读取接收到的数据 ​
    2.清除中断标志 ​
    3.记录按键被按下 ​
    4.更新计数值 ​
    5.通知主程序事件已经发生​
    中断服务函数一般要求执行时间尽量短，因为它会打断主程序运行。
  • 6.中断优先级​ 1
    当多个中断同时或接近同时发生时，CPU 需要先处理哪一个，这就要由中断优先级来决定。​
    优先级高的中断先执行，优先级低的中断后执行。​
    例如：​
    1.故障报警中断优先级高 ​
    2.普通按键中断优先级低​
    这样设计的目的，是保证更重要、更紧急的事件优先得到处理。​
    有些单片机还支持中断嵌套，也就是在执行低优先级中断时，如果来了更高优先级中断，CPU 可以先去处理更高优先级中断，之后再回来继续执行原来的中断。
  • 7.外部中断和内部中断
    按照中断来源不同，中断通常分为两类。

7.1 外部中断​
外部中断是由芯片外部信号引起的中断。 ​
例如：​
1.按键按下 ​
2.传感器输出变化 ​
3.外部设备发送触发信号

7.2 内部中断​
内部中断是由单片机内部外设产生的中断。 ​
例如：​
1.定时器溢出 ​
2.串口接收完成 ​
3.ADC 转换完成 ​
4.DMA 传输完成​
简单来说，外部中断来自芯片外部，内部中断来自芯片内部模块。

  • 8.中断与轮询的区别​
    1.轮询​
    轮询是主程序主动反复检查事件是否发生。 ​
    特点是结构简单，但效率较低。​
    2.中断​
    中断是事件发生后，由硬件主动通知 CPU 处理。 ​
    特点是响应及时，CPU 利用率更高。​
    因此，轮询适合简单场合，中断更适合实时性要求较高的场合。
  • 9.中断分组​
    中断分组是对 MCU 中断优先级的划分方式。​在 STM32 里，一个中断优先级通常分为两部分：​

  • 1.抢占优先级​
    决定某个中断能不能打断正在执行的另一个中断。​
    抢占优先级数值越小，优先级越高。​

  • 2.响应优先级（子优先级）​
    当两个中断的抢占优先级相同时，用响应优先级决定先响应哪个。​
    响应优先级数值越小，优先级越高。
    ​

  • 中断分组的作用​
    中断分组本质上就是分配“抢占优先级”和“响应优先级”各占几位。​
    不同分组方式，会影响中断嵌套能力和中断响应顺序。​
    例如：​
    •如果抢占优先级位数多，适合需要多层中断嵌套的场合。​
    •如果响应优先级位数多，适合中断很多但不强调嵌套的场合。​

  • 总结：​
    中断分组就是对中断优先级进行进一步划分，目的是让系统更合理地管理中断响应顺序和嵌套关系。

  • 10.NVIC​
    NVIC 是嵌套向量中断控制器，英文全称是 Nested Vectored Interrupt Controller。​
    它是 Cortex-M 内核中专门用来管理中断的模块。​
    主要作用：​
    1.管理中断的使能和关闭​
    2.设置中断优先级​
    3.实现中断嵌套​
    4.管理多个中断的响应顺序​
    简单理解：​
    NVIC 就像中断的“总指挥”，负责决定哪个中断先执行，哪个中断后执行，以及一个中断能不能打断另一个中断。
  • 11.外部中断中断线​
    外部中断线就是 MCU 用来接收外部信号并产生中断请求的通道。​
    当外部引脚电平发生变化时，可以通过外部中断线通知 CPU 进行处理。​
  • STM32 中常见特点：​
    1.外部中断线一般叫 EXTI​
    2.每一条中断线都可以对应某个 GPIO 引脚​
    3.可以配置为上升沿触发、下降沿触发或双边沿触发​
    4.外部中断常用于按键检测、传感器触发、输入信号捕获等场合​
  • 例如：​
    按键接在某个 IO 口上，当按键按下时，IO 电平变化，会触发对应的外部中断线，然后 CPU 进入中断服务函数处理事件。​
  • 总结：​
    外部中断线本质上是连接“外部引脚变化”和“CPU 中断响应”之间的桥梁。
  • 12.中断触发方式
    对于外部中断，通常可以设置不同的触发条件。​
    1.上升沿触发 ​
    引脚电平从低变高时触发中断。​
    2.下降沿触发 ​
    引脚电平从高变低时触发中断。​
    3.双边沿触发 ​
    只要电平发生变化就触发中断。​
    不同触发方式适用于不同的应用场景，例如按键检测常用下降沿或双边沿触发。

使用中断时要注意什么​
1.中断服务函数要尽量短 ​
不要在中断里写太多耗时操作。​
2.要及时清除中断标志 ​
否则可能会反复进入中断。​
3.主程序和中断中共用的变量要特别注意 ​
否则容易出现数据错误。​
4.优先级设置要合理 ​
防止重要中断得不到及时响应。

  • 总结​
    中断的核心，可以概括为一句话：​
    中断就是让单片机在执行主程序时，遇到重要事件能够暂停当前任务，优先处理该事件，处理完成后再回来继续执行原程序。​
    学习中断时，重点要理解以下几个概念：​
    1.中断源：谁产生了中断 ​
    2.中断请求：向 CPU 提出处理要求 ​
    3.中断服务函数：具体处理事件的程序 ​
    4.中断优先级：决定多个中断谁先执行 ​
    5.中断触发方式：事件在什么条件下触发中断

4.4 USART

  • 1.USART的概念
    USART 是 Universal Synchronous/Asynchronous Receiver Transmitter，中文一般叫通用同步/异步收发器。它是单片机中常用的一种串行通信外设，主要用于单片机和外部设备之间的数据交换。

在 STM32 中，USART 既支持同步通信，也支持异步通信，但实际开发中最常用的是异步通信。平时大家说的“串口通信”，大多数情况下就是指 USART 的异步工作方式。

USART 常用于：

  • STM32 与电脑串口助手通信
  • STM32 与蓝牙、WiFi、GPS 等模块通信
  • STM32 与其他单片机通信
  • 程序调试时输出日志信息

它的本质作用，就是把 CPU 内部的并行数据转换成串行数据发送出去，同时也能把接收到的串行数据重新还原成并行数据供程序使用。

  • 2.为什么需要 USART
    在单片机系统中，CPU 本身只能处理内部的数据和逻辑，但实际开发时，系统需要和外部模块、传感器、上位机等设备交换数据，因此必须使用通信接口。USART 就是最基础、最常用的一种通信方式。

USART 被广泛使用，主要有以下原因：

2.1 硬件连接简单
USART 在异步通信模式下，一般只需要：

  • TX：发送引脚
  • RX：接收引脚
  • GND：公共地

相比其他接口，它连接简单，排线方便，适合初学者快速上手。

2.2 使用场景广
USART 不仅可以用来传输正式业务数据，还可以用于调试。例如：

  • 打印变量值
  • 查看程序运行状态
  • 输出错误信息
  • 接收上位机命令

在 STM32 开发中，很多初学者接触的第一个通信外设就是 USART。

2.3 适合中低速串行通信
很多控制类和状态类数据传输，不要求特别高的速度，USART 完全能够满足需求，而且实现成本低、可靠性高。

  • 3.USART 的基本工作过程
    USART 的工作过程分为发送和接收两部分。

3.1 发送过程
当 STM32 要发送数据时，程序先把数据写入 USART 的发送数据寄存器，USART 外设会根据设定好的通信参数，把这个字节按位依次发送到 TX 引脚上，对方设备再按照相同规则接收这些数据。

发送时，数据不是整体发出去的，而是按照帧格式逐位发送，通常顺序如下：
1.起始位
2.数据位
3.校验位（如果配置了）
4.停止位

3.2 接收过程
当外部设备向 STM32 发送数据时，数据会从 RX 引脚进入 USART。USART 检测到起始位后，会按设定的波特率对后续位进行采样，然后将接收到的各个位重新组合成一个完整字节，存入接收数据寄存器，等待 CPU 读取。

如果程序读取不及时，而新数据又到了，就可能发生数据丢失或溢出错误。

  • 4.USART 和 UART 的区别
    USART 和 UART 很容易混淆，但它们并不是完全相同的概念。

UART 是 Universal Asynchronous Receiver Transmitter，即“通用异步收发器”，它只支持异步通信。

USART 是 Universal Synchronous/Asynchronous Receiver Transmitter，即“通用同步/异步收发器”，既支持同步通信，也支持异步通信。

所以可以这样理解：

  • UART 只能异步通信
  • USART 可以同步，也可以异步
  • 当 USART 工作在异步模式下时，它的用法和 UART 很像

在 STM32 开发中，虽然很多外设名称叫 USART，但实际大部分使用场景还是异步串口通信。

  • 5.USART 的常见参数
    USART 通信能否正常进行，关键在于通信双方的参数必须一致。常见参数主要有以下几种。

5.1 波特率
波特率表示每秒传输的符号数，常见取值有：

  • 9600
  • 19200
  • 38400
  • 57600
  • 115200

如果双方波特率不一致，通常会出现乱码。

5.2 数据位
数据位表示一帧中有效数据的位数，常见有 8 位和 9 位，大多数情况下使用 8 位。

5.3 停止位
停止位表示一帧数据结束，常见为 1 位停止位或 2 位停止位，一般常用 1 位。

5.4 校验位
校验位用于简单检错，常见设置包括：

  • 无校验
  • 奇校验
  • 偶校验

5.5 工作模式
USART 可以配置成：

  • 仅发送
  • 仅接收
  • 发送和接收同时开启

在实际使用中，通常会同时开启发送和接收功能。

  • 6.USART 的数据帧格式
    USART 在异步通信时，数据是按“帧”发送的。一帧数据通常由以下几个部分组成。

6.1 起始位
起始位表示一帧数据的开始，通常为低电平。接收方检测到这个低电平后，就知道一帧新数据开始了。

6.2 数据位
数据位是真正要传输的数据内容，通常为8位，按照规定顺序逐位发送。

6.3 校验位
如果启用了校验功能，数据位之后会附加一位校验位，用于帮助检测传输中是否出现错误。

6.4 停止位
停止位用于表示一帧数据结束，通常为高电平。

最常见的串口格式是 8N1，表示：

  • 8 位数据位
  • 无校验
  • 1 位停止位

这是最常见、最基础的一种 USART 配置格式。

  • 7.USART 的收发方式​
    USART 常见的收发方式主要有三种：查询方式、中断方式和 DMA 方式。​
    UART的数据链路：

7.1 查询方式
查询方式也叫轮询方式，就是 CPU 不断检查 USART 的状态标志位，判断是否可以发送、是否收到数据。
优点是实现简单，适合入门学习。
缺点是 CPU 会一直等待，效率较低。

7.2 中断方式
中断方式是在 USART 收到数据或满足某种条件时，主动通知 CPU 进行处理。这样 CPU 平时不需要一直盯着串口状态，效率更高。
这是项目中非常常见的一种方式，尤其适合接收命令、接收短数据帧等场景。

7.3 DMA 方式
DMA 可以直接帮助 USART 在外设和内存之间搬运数据，不需要 CPU 一字节一字节参与。它适合数据量较大、收发较频繁的场景。

例如：

  • 连续打印大量日志
  • 高速接收一串数据
  • 接收不定长数据帧
  • 8.使用 USART 时要注意什么
    USART 虽然简单，但实际使用时仍然有一些非常常见的问题需要注意。

8.1 参数必须一致
通信双方的波特率、数据位、停止位、校验位必须一致，否则容易出现乱码或无法通信。

8.2 引脚连接要正确
正确连接方式应为：

  • 本机 TX 接对方 RX
  • 本机 RX 接对方 TX
  • 双方 GND 共地

8.3 中断中不要处理太重
如果使用中断接收，在中断服务函数中应尽量只做接收和缓存，不要在中断里进行复杂解析或耗时操作，否则容易影响系统实时性，甚至导致丢数据。

8.4 注意数据边界
USART 本质上是字节流，不会自动区分“一帧数据从哪里开始，到哪里结束”。所以在正式项目中，通常要自己设计通信协议，例如使用：

  • 固定长度
  • 帧头帧尾
  • 长度字段
  • 校验字段

8.5 注意常见故障
USART 常见问题包括：

  • 串口乱码
  • 接收不到数据
  • 数据丢失
  • 波特率不匹配
  • 接地不良
  • 缓冲区处理错误

因此在调试时，既要检查软件配置，也要检查硬件连接和时钟设置。

4.5 STM32H747XIH6内存布局

  • 1.什么是 STM32H747XIH6 的内存布局
    STM32H747XIH6 的“内存布局”，就是芯片内部各种 Flash 和 RAM 在地址空间里的分布方式。

和普通单片机不一样，STM32H747XIH6 不是只有“一块 Flash + 一块 RAM”，而是把内存分成了很多区域，每个区域的位置、速度、访问方式、适合的用途都不同。

所以学习这颗芯片的内存布局，重点不是死记地址，而是先明白：

  • 哪些区域是放程序的
  • 哪些区域是放变量的
  • 哪些区域速度最快
  • 哪些区域适合 DMA
  • 哪些区域适合双核共享
  • 哪些区域掉电后还能保留数据
  • 2.为什么 STM32H747XIH6 要把内存分成这么多块
    STM32H747XIH6 是一颗双核 MCU，内部有：
  • Cortex-M7
  • Cortex-M4

同时芯片内部还有多个总线域：

  • D1 域
  • D2 域
  • D3 域

不同的内存块挂在不同的总线和域上，所以访问性能和用途也不同。

这样设计的目的很明确：

  • 让高速核心访问关键数据更快
  • 让 DMA 访问数据更方便
  • 让双核之间更容易分工
  • 让低功耗场景下还能保留部分数据

所以它的内存不是“乱”，而是“按用途拆开”。

  • 3.先认识两大类内存：Flash 和 RAM
    在 STM32H747XIH6 里，可以先把内存分成两大类。

3.1 Flash 是干什么的
Flash 主要用来存放程序代码和长期保存的数据。
特点是：

  • 断电后数据不会丢失
  • 适合放程序
  • 也可以放常量、查找表、配置参数

在 STM32H747XIH6 中，Flash 分成两个 Bank，这对双核启动和程序分区很有帮助。

3.2 RAM 是干什么的
RAM 主要用来存放程序运行时的数据。
比如：

  • 全局变量
  • 局部变量
  • 栈
  • 堆
  • DMA 缓冲区
  • 图像缓存
  • 双核共享数据

特点是：

  • 速度快
  • 运行时可读可写
  • 断电后通常会丢失

STM32H747XIH6 的 RAM 又被分成很多块，不同块的用途不一样。

  • 4.ITCM 和 DTCM 是干什么的
    这两块内存是先要重点理解的，因为它们和普通 SRAM 不一样。

4.1 ITCM 是什么
ITCM 是给 Cortex-M7 核心准备的高速指令内存。
它主要用来放：

  • 对执行速度要求非常高的代码
  • 中断服务函数
  • 实时性要求极强的关键函数

它的特点是：

  • 访问速度非常快
  • 适合执行代码
  • 更强调“确定性”

可以简单理解成：
这是专门给 M7 准备的“跑关键代码的小高速区”。

4.2 DTCM 是什么
DTCM 是给 Cortex-M7 核心准备的高速数据内存。
它主要用来放：

  • 中断中频繁访问的数据
  • 栈
  • 堆
  • 实时算法变量
  • 对访问延迟很敏感的数据

它的特点是：

  • 访问速度很快
  • 适合存放关键数据
  • 很适合 M7 的高实时任务

可以简单理解成：
这是专门给 M7 放“关键数据”的高速区。

4.3 初学者怎么理解 TCM​
可以把 TCM 理解成：​

  • ITCM：放关键代码​
  • DTCM：放关键数据​
    如果程序里有一部分内容必须跑得特别快、特别稳，就优先考虑这两块。
  • 5.AXI SRAM 是干什么的
    AXI SRAM 是 STM32H747XIH6 内部最大的一块通用 RAM。

它主要适合放：

  • 大数组
  • 大块全局变量
  • 图像缓冲区
  • 显示缓存
  • 一般业务数据

它的特点是：

  • 容量大
  • 通用性强
  • 很适合 M7 做主业务处理

如果你做的是：

  • GUI
  • LVGL
  • LCD 刷屏
  • 图像处理
  • 较大的数据缓存

那么 AXI SRAM 往往是最常用的一块 RAM。

可以简单理解成：
这是芯片里的“大仓库”。

  • 6.SRAM1、SRAM2、SRAM3 是干什么的
    这三块 SRAM 位于 D2 域，通常和外设、DMA、M4 核关系更紧密。

6.1 SRAM1 的用途
SRAM1 适合放：

  • DMA 缓冲区
  • M4 使用的数据
  • 外设收发缓存
  • 双核共享的一般数据

6.2 SRAM2 的用途
SRAM2 和 SRAM1 类似，也适合放：

  • DMA 数据
  • M4 读写数据
  • 外设中间缓存
  • 双核共享数据

6.3 SRAM3 的用途
SRAM3 容量比前两块小，但很常用于：

  • Ethernet 缓冲
  • USB 缓冲
  • 双核共享数据
  • 特定通信缓冲区

6.4 初学者怎么理解 D2 域 SRAM
可以先把 SRAM1、SRAM2、SRAM3 理解成：

  • 更适合外设和 DMA 配合
  • 更适合 M4 使用
  • 也很适合做 M7 和 M4 之间的共享区

如果你以后遇到“DMA 放哪”“M4 数据放哪”“双核共享区放哪”，通常就会想到这几块。

  • 7.SRAM4 是干什么的
    SRAM4 位于 D3 域。

它适合放：

  • D3 域相关数据
  • BDMA 缓冲区
  • 双核共享数据
  • 低功耗模式下希望保留的数据

它的特点是：

  • 属于 D3 域
  • 在低功耗设计里比较有价值
  • 也能用作共享内存

可以简单理解成：
这是“更偏系统域、低功耗、共享用途”的一块 RAM。

  • 8.Backup SRAM 是干什么的
    Backup SRAM 是备份 SRAM。

它主要适合放：

  • 需要掉电后尽量保留的小数据
  • 系统状态标志
  • 唤醒信息
  • 运行计数
  • RTC 配套数据

它的特点是：

  • 容量很小
  • 但有特殊价值
  • 在 VBAT 供电存在时，可以在某些低功耗模式下保留数据

可以简单理解成：
这是专门存“小而重要信息”的地方。

  • 9.Flash 两个 Bank 是怎么理解的
    STM32H747XIH6 的片内 Flash 总共 2 MB，分成两个 Bank。

这样分的好处是：

  • 双核程序更容易分开存放
  • 升级和擦写时更灵活
  • 代码区规划更清楚

在很多工程里，常见做法是：

  • M7 程序放在 Bank1
  • M4 程序放在 Bank2

这样一看就清楚，也方便管理双核工程。

  • 10.学内存布局时，小白最该先记住什么

  • ITCM：放 M7 的关键代码

先把“干什么用”理解了，再看地址就会轻松很多。

4.6 MPU

4.6.1 MPU是什么

在 STM32 里，MPU 指的是 Memory Protection Unit，中文一般叫“内存保护单元”。

MPU 的作用，不是增加内存，而是给现有内存设置访问规则。
CPU 在访问某一段地址空间时，要按照 MPU 预先配置好的属性进行访问。

MPU 主要完成以下几类控制：

  • 限制某块内存能不能访问
  • 限制访问权限是只读还是可读写
  • 控制某块内存能不能执行代码
  • 控制某块内存是否使用 Cache
  • 控制某块内存是否 Bufferable、是否 Shareable

可以把 MPU 理解成下面这个过程：

  • 先把内存划分成若干区域
  • 再给每个区域配置访问规则
  • CPU 访问该区域时必须遵守这些规则
  • 如果访问方式不符合规则，就会触发异常

所以，MPU 的本质是管理“内存访问方式”，而不是管理“内存里的数据内容”。

在 STM32 中，MPU 常见于带有 Cortex-M 内核的芯片，尤其是 Cortex-M7。
在 STM32H7 这类芯片中，MPU 使用非常普遍，因为它与 Cache、DMA、外部存储器、任务隔离等内容关系密切。

4.6.2 MPU 的区域划分方式

MPU 的工作单位不是单个变量，而是一整段地址空间，也就是一个 Region。
也就是说，MPU 不是针对某个变量单独设置权限，而是对某一段连续地址统一设置规则。

例如：

  • 从 0x30000000 开始的一段内存设为可读写、不可执行
  • 从 0x24000000 开始的一段内存设为可缓存
  • 某一段外部存储区设为只读

每个 Region 通常需要配置以下内容：

  • 起始地址
  • 区域大小
  • 访问权限
  • 执行权限
  • Cache 属性
  • Buffer 属性
  • Shareable 属性

在配置 Region 时，有两个基本限制需要注意。

第一，区域大小通常必须是 2 的幂。
常见大小包括：

  • 32B
  • 64B
  • 128B
  • 256B
  • 512B
  • 1KB
  • 2KB
  • 4KB
  • 8KB
  • 16KB
  • 32KB
  • 64KB
  • 128KB
  • 256KB
  • 512KB
  • 1MB

这意味着不能随意定义一个 20KB 或 50KB 的 MPU 区域。

第二，区域起始地址通常需要按区域大小对齐。
例如：

  • 如果区域大小是 32KB
  • 那么起始地址一般要按 32KB 对齐

如果地址不对齐，配置结果就不符合 MPU 规则。

因此，MPU 配置的第一步，通常不是先写代码，而是先确定：

  • 这块内存从哪里开始
  • 准备覆盖多大范围
  • 大小是否符合 2 的幂要求
  • 地址是否满足对齐要求

4.6.3 MPU 的访问权限与执行权限

MPU 的一个核心功能，就是控制某块内存“能不能访问”和“怎么访问”。

访问权限主要用来规定：

  • 是否允许访问
  • 是否允许写
  • 是否只允许读
  • 是否仅允许特权级访问

在实际工程中，常见的访问控制方式包括：

  • No Access：禁止访问
  • Read Only：只读
  • Full Access：可读可写

这些权限的作用非常直接。
如果一个区域被设成只读，那么程序去写这块区域时，就会触发异常。
如果一个区域被设成禁止访问，那么任何读写操作都会被 MPU 拦截。

除了读写权限，MPU 还可以控制“能不能执行代码”。
这项功能通常叫做 Execute Never，也就是“禁止执行”。

它的作用是：

  • 允许这块内存只存数据
  • 不允许 CPU 从这里取指执行

这在数据区里非常重要。
例如一段 SRAM 本来只是作为缓存区使用，如果程序因为异常跳转到了这里，CPU 可能会把数据内容当成指令执行。
如果提前把这块区域设成不可执行，那么这类问题就会立刻捕获。

因此，访问权限解决的是“能不能读写”，执行权限解决的是“能不能当代码跑”。

4.6.4 MPU 的 Cache、Buffer 和 Shareable 属性

在 STM32H7 中，MPU 最重要的实际用途之一，是配置内存属性，而不只是做权限保护。

内存属性里最常见的三个：

  • Cacheable
  • Bufferable
  • Shareable

1.Cacheable
Cacheable 表示这块内存是否允许被 Cache。
如果设置为可缓存，那么 CPU 访问这块区域时，数据可能会先进入 Cache，后续读写也可能直接和 Cache 交互，而不是每次都访问实际内存。
这样做的优点是速度快。
但如果这块内存同时也被 DMA 使用，就可能产生一致性问题。

2.Bufferable
Bufferable 表示这块内存访问时是否允许缓冲。
开启缓冲后，写操作不一定立刻落到最终目标，而可能先进入写缓冲区。
这有助于提高某些访问效率，但也会让访问行为变得更复杂。
在很多 DMA 相关场景中，为了减少不确定性，通常会把 DMA 缓冲区设成不可缓冲。

3.Shareable
Shareable 表示这块内存是否被多个总线主设备共享。
如果一块内存既可能被 CPU 访问，也可能被 DMA、以太网控制器、USB 控制器等主设备访问，那么它通常更适合设置为共享属性。
这项属性与系统一致性和总线行为有关，在涉及多个主设备访问同一块内存时比较重要。

因此，MPU 不只是做“访问允许或禁止”的控制，它还决定了 CPU 访问内存时采用什么样的行为模式。
在 H7 这类带 Cache 的系统中，这部分内容往往比单纯的读写权限更关键。

4.6.5 MPU 和 DMA、Cache 的关系

在 STM32H7 中，MPU 最典型的应用场景，就是处理 DMA 和 D-Cache 之间的数据一致性问题。

先看一个常见场景：

  • CPU 定义了一个接收缓冲区
  • DMA 不断把外设数据写入这个缓冲区
  • CPU 再去读取缓冲区内容进行处理

如果这个缓冲区所在区域是 Cacheable，就会出现下面的问题：

  • DMA 写入的是实际内存
  • CPU 读到的可能是 Cache 里的旧数据
  • CPU 和 DMA 看到的数据不一致

这样就会出现一种现象：

  • DMA 明明已经收到了新数据
  • 但 CPU 读出来还是旧值
  • 程序表现得像 DMA 没更新一样

问题的根源不在 DMA，而在 Cache。
因为对于 CPU 来说，它可能并没有重新从实际内存存取数据，而是继续使用了之前缓存下来的内容。

解决这类问题通常有两种方法：

第一种，手动维护 Cache。
例如在 DMA 接收完成后，手动执行 D-Cache invalidate；
在 DMA 发送前，手动执行 D-Cache clean。
这种方法控制精细，但使用时必须非常小心，遗漏一次就可能出问题。

第二种，使用 MPU 把 DMA 缓冲区配置成 Non-Cacheable。
这样 CPU 对这块区域的访问不会经过 D-Cache，DMA 和 CPU 访问的都是同一份实际内存数据。
这种方法更直观，也更适合长期稳定运行的工程。

因此，在 H7 项目里，很多 MPU 配置的核心目的就是：

  • 为 DMA 单独划出一块内存区域
  • 把这块区域设成不可缓存
  • 让 DMA 和 CPU 数据一致

这也是学习 STM32H7 的 MPU 时最应该优先理解的内容。

4.6.6 MPU 在 STM32 中的典型用途

MPU 在 STM32 工程中的常见用途主要有以下几类。

1.保护非法地址访问
有些地址区域不应该被程序访问。
例如未使用空间、保留地址、非法地址范围等。
可以把这些区域设置成禁止访问。
这样一旦程序越界、野指针访问、栈破坏导致错误寻址，就能立刻触发异常。

2.设置只读区域
某些数据在运行时不应该被修改，例如：

  • 参数表
  • 常量表
  • 查找表
  • 关键配置数据

这类区域可以设置为只读。
如果程序误写，就会被 MPU 检测出来。

3.设置数据区禁止执行
对于纯数据存储区，例如：

  • 普通变量区
  • DMA 缓冲区
  • 堆区
  • 栈区

通常都不需要执行代码。
将这些区域设置为禁止执行，可以减少程序跑飞后误执行数据内容的风险。

4.为 DMA 缓冲区配置非缓存属性
这是 STM32H7 中最常见的用途之一。
做法通常是：

  • 在某块 SRAM 中划出一段区域
  • 专门用于 DMA 缓冲
  • 通过 MPU 设置为 Non-Cacheable

这样可以避免 DMA 和 CPU 数据不一致。

5.配置外部存储器访问属性
对于外部 SDRAM、QSPI Flash 等区域，访问性能、可执行性、缓存策略往往都需要单独考虑。
MPU 可以为这些外部存储区配置合适的属性，使系统性能和稳定性更好。

4.6.7 MPU 的配置流程

在 STM32 中配置 MPU，一般遵循固定流程。

1.先确定目标区域
需要先明确：

  • 哪一段地址需要配置
  • 起始地址是多少
  • 覆盖范围多大
  • 是否满足对齐要求
  • 区域大小是否是 2 的幂

这一步是整个配置的基础。

2.明确该区域的用途
要先判断这块区域是做什么的，例如：

  • 普通数据区
  • DMA 缓冲区
  • 外部 SDRAM
  • 代码执行区
  • 只读区

不同用途，决定了不同配置方式。

3.根据用途确定属性
例如要考虑：

  • 是只读还是可读写
  • 是否允许执行
  • 是否允许 Cache
  • 是否需要 Bufferable
  • 是否需要 Shareable

这一步决定了 MPU 配置的具体内容。

4.关闭 MPU
配置前通常先关闭 MPU，避免在配置过程中出现不一致状态。

5.配置 Region
逐个设置每个 Region 的参数，包括：

  • Region 编号
  • 基地址
  • 大小
  • 权限
  • 执行属性
  • Cache 属性
  • Buffer 属性
  • Shareable 属性

6.重新使能 MPU
配置完成后，再使能 MPU，让配置正式生效。

7.进行功能验证
配置完成后，通常需要验证：

  • DMA 是否正常工作
  • CPU 读写是否正常
  • 是否还存在 Cache 一致性问题
  • 是否触发了异常
  • 目标区域是否真的落在预期地址范围内

MPU 配置不能只看代码是否写完，更重要的是验证这块区域是否真的按照预期工作。

4.6.8 学习 MPU 时容易出现的问题

在 STM32 中学习和使用 MPU 时，常见问题主要集中在以下几个方面。

1.区域大小设置错误
MPU 区域大小通常必须是 2 的幂。
如果随意定义一个不符合规则的大小，配置就不正确。

2.起始地址没有按区域大小对齐
例如定义一个 32KB 区域，但起始地址并没有按 32KB 对齐，这样配置出来的区域就可能出错。

3.变量并没有放进目标区域
有时候 MPU 配置本身没有问题，但变量实际并不在这片地址空间里。
例如希望 DMA 缓冲区在非缓存区，但链接脚本没有把变量真正放进去，最后 MPU 配置和实际变量地址不对应。

4.只看权限，不看内存属性
很多初学者会把 MPU 只理解成“只读、可写、禁止访问”，但在 H7 中，更关键的问题往往是 Cache 属性。
如果忽略 Cacheable、Bufferable、Shareable，很多 DMA 问题就很难解释。

5.忽略区域重叠问题
多个 Region 之间如果发生重叠，最终生效结果会与区域优先级有关。
如果没有理清覆盖关系，实际访问行为可能和预期不一致。

6.配置完成后没有做验证
MPU 配置不是“代码写上就一定正确”。
必须通过实际读写、DMA 运行、异常测试等方式验证它是否真正生效。

4.6.9 MPU 的理解重点

学习 STM32 的 MPU，重点不是记住多少配置项，而是先把下面几个问题理清楚。

第一，MPU 管的是区域。
每次配置 MPU，本质上都是在给一段地址空间设规则，而不是给某个变量单独加属性。

第二，MPU 既管权限，也管属性。
它既能控制：

  • 能不能访问
  • 能不能写
  • 能不能执行

也能控制：

  • 是否走 Cache
  • 是否 Bufferable
  • 是否 Shareable

第三，MPU 的价值在 STM32H7 上尤其明显。
因为 H7 的内存系统更复杂，DMA 和 Cache 的关系更敏感。
很多系统稳定性问题、数据一致性问题，本质上都与 MPU 配置有关。

第四，MPU 必须结合实际工程理解。
如果脱离 DMA、Cache、外部存储器这些实际场景，MPU 容易只剩下抽象概念。
结合具体工程去理解，才能真正明白它的作用。

MPU 可以概括为一句话：
MPU 的作用，就是为内存区域定义访问规则和访问属性，让系统运行更加安全、稳定、可控。

4.7 Cache

  • STM32H7 的 Cache 是什么
    在 STM32H7 里，Cache 可以理解成：
    放在 CPU 旁边的一小块“高速临时存储”。

因为 CPU 运行速度很快，但访问 RAM、Flash 这些存储器会慢一些，所以 CPU 不会每次都直接去外部存储区域拿数据或指令，而是会先把“最近可能要用的内容”放到 Cache 里。这样下次再用时，就能更快拿到。

所以 Cache 的核心作用就一句话：
减少 CPU 访问慢速存储器的次数，提高执行效率。

  • 为什么 H7 需要 Cache
    STM32H7 是高性能系列，主频高，核心快。
    CPU 越快，就越容易遇到一个问题：
    CPU 等存储器，等得太久。

比如：

  • 取一条指令要去 Flash 里拿
  • 读一个变量要去 SRAM 里拿
  • 访问数组时要反复读内存

如果每次都老老实实去原始存储区域访问，CPU 的速度就发挥不出来。
这时候 Cache 的作用就是：
把常用内容提前放到离 CPU 更近的位置。

  • Cache 缓存的是什么
    在 STM32H7 里，先只需要知道两类：
    1.I-Cache
    Instruction Cache，也就是指令缓存。
    它缓存的是程序指令。

比如 CPU 正在执行 main() 里的代码，这些代码本来在 Flash 里，CPU 取过一次之后，可能就先放进 I-Cache，后面再执行附近的代码时就更快。

可以理解成：
I-Cache 是帮 CPU 更快“读代码”的。

2.D-Cache
Data Cache，也就是数据缓存。
它缓存的是程序运行时要访问的数据，比如：

  • 变量
  • 数组
  • 结构体
  • 内存中的缓冲区

可以理解成：
D-Cache 是帮 CPU 更快“读写数据”的。

  • Cache 为什么会加速
    因为程序运行时，常常有一个特点：
    刚访问过的东西，很可能很快还会再访问一次。

举个很简单的例子：

CPU 在处理这个循环时，会连续访问一段相邻内存。
如果没有 Cache，每次都要去 SRAM 里读。
有了 Cache，CPU 可能一次把附近一小片数据先搬到 Cache 里，后面访问 buf[i]、buf[i+1]、buf[i+2] 时，就可以直接从 Cache 拿。

所以 Cache 加速，靠的不是“算得更快”，而是：
少跑远路，多用手边已经拿到的内容。

  • Cache 和原始内存是什么关系
    这里最容易混淆。
    Cache 不是用来替代 RAM 或 Flash 的，
    它更像是 CPU 前面的一个“临时副本区”。

也就是说：

  • 真正的程序代码，通常还在 Flash
  • 真正的数据，通常还在 SRAM
  • Cache 里放的是这些内容的一部分副本

所以 CPU 在运行时，并不是永远直接面对 Flash 和 SRAM，
很多时候它先面对的是 Cache。
这个认知很重要。

  • 访问内存时到底发生了什么
    可以这样粗略理解：
    CPU 要读一个东西时
    CPU 先看 Cache 里有没有。
  • 如果有，直接拿走，这就比较快
  • 如果没有，再去原始存储器里拿，同时可能顺手放进 Cache，方便下次再用

这就是常说的：

  • Cache Hit：命中缓存
  • Cache Miss：没命中缓存

命中越多，程序通常越快。

CPU 要写一个东西时：
情况会稍微复杂一点，但先简单理解就够了：
CPU 写数据时，不一定立刻写到最终内存里，
它可能先改 Cache 里的内容，之后再找机会写回 RAM。

这也是为什么后面会出现 Cache 一致性问题。

不过你现在先只记住这个事实：
CPU 看到的数据，有时是 Cache 里的；内存里的内容，未必立刻同步。

  • 对 STM32H7 来说，最本质的理解
    学 H7 的 Cache，不需要一开始就背很多术语。
    先建立这个最重要的画面就够了：
    CPU 和内存之间，多了一层高速缓冲。

于是程序运行时就变成了这样：

  • 取指令，可能先从 I-Cache 取
  • 读数据，可能先从 D-Cache 取
  • 写数据，也可能先写进 D-Cache

所以 Cache 带来的本质变化不是“多了一块内存”，而是：
CPU 访问内存这件事，不再总是直接发生。

STM32H7 的 Cache，本质上就是：
为了让 Cortex-M7 核心少等待存储器，而增加的一层高速缓存机制。

它的价值是提速；
它的复杂点在于，CPU 看到的内容和内存里的实际内容，有时候不会立刻完全一致。

4.8 DMA

  • 1.DMA的概念
    DMA 是 Direct Memory Access，中文一般叫“直接存储器访问”。

它是一种专门用来搬运数据的硬件机制。正常情况下，数据在外设和存储器之间传输时，需要 CPU 参与，例如 CPU 先从外设寄存器读出数据，再写到内存里；或者从内存中取出数据，再写到外设寄存器中。而 DMA 的作用，就是在不需要 CPU 反复参与的情况下，自动完成这些数据搬运工作。

在 STM32 中，DMA 常用于下面这些场景：

  • 串口接收和发送数据
  • ADC 采样数据自动存入数组
  • SPI 大量收发数据
  • DAC 自动输出波形
  • 存储器之间的数据拷贝

DMA 的核心意义在于：让数据搬运这件事交给硬件做，CPU 只负责控制和处理结果。

  • 2.为什么需要 DMA
    在单片机系统中，CPU 既要执行程序逻辑，又要处理中断，还要控制各种外设。如果每一份数据都由 CPU 亲自搬运，那么在数据量较大或传输较频繁时，CPU 的负担会明显增加。

使用 DMA 的主要原因有以下几点。

2.1 减轻 CPU 负担
例如串口连续接收数据时，如果每来一个字节都要 CPU 进入中断读取，再写入缓冲区，那么 CPU 会不断被打断。
使用 DMA 后，数据可以自动写入内存，CPU 不需要逐字节参与。

2.2 提高传输效率
DMA 属于硬件级搬运，速度快，适合连续、大批量的数据传输。特别是在 ADC 连续采样、SPI 屏幕刷新、串口大数据接收这些场景中，DMA 的优势会很明显。

2.3 提高系统实时性
CPU 不再被大量“搬数据”的工作占用，就可以把更多时间留给控制逻辑、通信协议处理、算法运算等任务，从而提升整个系统的实时响应能力。

  • 3.DMA 的基本工作过程
    DMA 的工作本质就是：按照配置好的规则，把数据从一个地址搬到另一个地址。

它的基本流程通常如下：

  1. 配置源地址
  2. 配置目标地址
  3. 配置搬运的数据数量
  4. 配置数据宽度和传输方向
  5. 使能 DMA
  6. DMA 自动开始搬运数据
  7. 传输完成后置位标志，或者产生中断通知 CPU

例如串口接收时：

  • 源地址是串口数据寄存器
  • 目标地址是内存缓冲区
  • 每收到一个字节，DMA 自动写入数组
  • 数据满了以后，DMA 触发完成标志或完成中断

也就是说，CPU 前面做的是“配置”，后面做的是“处理结果”，中间大量重复的数据搬运由 DMA 自动完成。

  • 4.DMA 的传输方向
    DMA 的传输方向主要有三种，理解这个很重要。

4.1 外设到存储器
这是最常见的一种方式。外设产生数据，DMA 自动把数据搬运到内存中。
典型例子：

  • USART 接收数据到数组
  • ADC 采样值写入缓冲区
  • SPI 接收数据写入内存

4.2 存储器到外设
数据先放在内存里，再由 DMA 自动送到外设。
典型例子：

  • USART 发送缓冲区数据
  • DAC 输出波形表
  • SPI 发送显示数据到屏幕

4.3 存储器到存储器
DMA 也可以把一块内存中的数据复制到另一块内存。
这种方式常用于：

  • 数组拷贝
  • 缓冲区搬运
  • 某些高效数据复制场景
  • 5.DMA 的几个重要参数
    使用 DMA 时，最核心的就是把几个关键参数配置正确。

5.1 源地址和目标地址
DMA 搬数据一定要知道“从哪里搬”和“搬到哪里去”。
例如：

  • 串口接收：从 USART 数据寄存器 搬到 接收数组
  • 串口发送：从 发送数组 搬到 USART 数据寄存器

5.2 传输数据个数
DMA 需要知道一共要搬多少个数据单位。
例如：

  • 接收 100 个字节
  • 发送 256 个采样点
  • 搬运 50 个半字数据

如果数量设置错了，就可能出现数据不完整、越界或者提前结束。

5.3 数据宽度
DMA 传输的数据宽度通常可以配置为：

  • 字节 8位
  • 半字 16位
  • 字 32位

这个宽度要和外设数据寄存器及目标缓冲区相匹配。
例如串口一般按字节传输，ADC 常按半字传输。

5.4 地址是否自增
DMA 可以配置地址是否自动递增。

  • 外设地址一般不自增，因为寄存器地址通常固定
  • 存储器地址一般自增，因为数据要依次写入数组中的不同位置

如果这个参数配错，常常会导致所有数据都写到同一个位置。

5.5 模式选择
DMA 常见模式包括：

  • 普通模式
  • 循环模式

普通模式下，搬完设定数量后就停止。
循环模式下，搬完以后会重新从头开始，适合持续不断的数据流场景。

  • 6.DMA 的工作模式
    6.1 普通模式
    普通模式是最基础的模式。DMA 在完成设定数量的数据搬运后，会自动停止。

适合场景：

  • 一次性发送一段串口数据
  • 一次性接收固定长度的数据
  • 一次性完成数组拷贝

这种模式的特点是逻辑简单，适合固定长度传输。

6.2 循环模式
循环模式下，DMA 在搬完设定数量后不会停止，而是从缓冲区起始位置重新开始。

适合场景：

  • ADC 连续采样
  • 串口持续接收数据流
  • DAC 周期输出波形
  • 长时间实时采样系统

循环模式的优点是适合持续运行，但程序必须注意缓冲区中的数据何时有效、是否会被新数据覆盖。

  • 7.DMA 中断与标志位
    DMA 在工作过程中会产生一些重要标志，必要时也可以触发中断。

7.1 传输完成标志
当 DMA 把设定数量的数据全部搬运完成后，会置位传输完成标志。程序可以通过查询该标志，或者进入 DMA 中断来知道传输结束。

7.2 半传输标志
有些 DMA 支持半传输标志，即数据搬运到一半时先给出提示。
这个功能常用于双缓冲或循环接收场景，例如：

  • 一半缓冲区数据可先处理
  • 另一半继续由 DMA 填充

7.3 错误标志
如果 DMA 在传输中出现配置错误或访问异常，可能会置位错误标志。虽然基础实验中不一定经常碰到，但项目开发里仍然要注意检查。

7.4 DMA 中断的作用
DMA 中断常用于：

  • 通知一段数据发送完成
  • 通知一批采样数据接收完成
  • 通知 CPU 可以开始处理缓冲区中的内容

DMA 中断和串口中断的区别在于：
串口中断往往是“来一个字节处理一次”，而 DMA 中断通常是“搬完一批数据再处理一次”。

  • 8.DMA 的典型应用与注意事项
    DMA 最常见的应用，通常都和“持续搬运数据”有关。

8.1 USART + DMA
在串口中，DMA 经常用于：

  • 串口发送一整段缓冲区数据
  • 串口接收一串连续数据

例如接收场景中，DMA 自动把串口收到的数据写入数组，CPU 不用逐字节搬运。
如果是不定长串口接收，往往还会结合空闲中断一起使用，这样既能自动收数据，又能知道一帧什么时候结束。

8.2 ADC + DMA
ADC 连续采样时，每个采样值都要保存下来。如果每次转换完成都让 CPU 去读寄存器，会很占资源。DMA 可以直接把每次采样结果放进数组中，非常适合波形采样、传感器连续采样等场景。

8.3 使用 DMA 时要注意什么
使用 DMA 时最容易出问题的地方主要有这些：

  1. 源地址和目标地址配置反了
  2. 数据宽度配置不匹配
  3. 地址自增设置错误
  4. 缓冲区长度设置错误
  5. 循环模式下数据被覆盖却没有及时处理
  6. 传输完成后没有正确清标志
  7. 外设没有正确开启 DMA 请求

很多时候 DMA 本身并不难，真正容易出问题的是“DMA 配置”和“外设配合”。

10.2 空闲中断接收数据
空闲中断，通常也叫 UART IDLE 中断，它并不是指 CPU 空闲了，而是指串口接收线在一段时间内没有再收到新的数据。更准确地说，当串口已经接收过数据，随后 RX 线上持续保持空闲状态，并且这个空闲时间达到 1 个字符帧时间时，串口硬件就会置位 IDLE 标志；如果提前使能了 IDLE 中断，CPU 就会进入中断服务函数。这就是“空闲中断”的本质。

为什么要用空闲中断？因为串口通信里经常会遇到一种情况：数据长度不固定。比如上位机可能一次发来 7 个字节，也可能一次发来 23 个字节，单片机事先并不知道这一包到底多长。如果只用普通接收中断，往往要每收到 1 个字节就进一次中断，CPU 会比较忙；如果只用 DMA，又常常只能按照固定长度去搬运数据，不太容易判断“一包数据什么时候结束”。这时候，空闲中断就很有用了，它相当于在告诉单片机：这一段数据已经发完了，现在可以开始处理了。

可以把它理解成这样：发送端正在连续发数据时，接收线是忙碌的；一旦这一串数据发送完成，中间出现了一个明显的停顿，串口硬件就认为线路“空闲”了，于是触发空闲中断。所以，空闲中断本质上不是用来接收某个字节，而是用来判断一帧或一包数据的结束时机。这也是它在串口协议处理里特别常见的原因。

在实际工程里，空闲中断最经典的搭配就是 DMA + UART 空闲中断。DMA 负责把串口收到的数据自动搬运到接收缓冲区，这样 CPU 不需要每收一个字节都处理；空闲中断负责在数据暂停时通知 CPU，CPU 再去统计 DMA 一共收了多少字节，然后把这一包数据取出来解析。这样做的好处很明显：既减轻了 CPU 负担，又能很好地处理变长数据包，所以在 STM32、尤其是串口通信比较频繁的场景里，这是一种非常常见的写法。

需要注意的是，空闲中断的触发依据并不是“协议上的一帧”，而只是“线路上出现了一段空闲时间”。也就是说，它识别的是时间间隔，不是协议内容本身。如果发送方在一包数据中间停顿过久，接收方也可能提前认为这一包结束了。所以在实际应用中，空闲中断通常要结合协议规则一起使用，比如包头、长度字段、校验和、结束符等，这样才能更可靠地完成数据解析。

还有一个容易混淆的点：空闲中断不是 DMA 中断，它本质上还是 UART 外设产生的中断。DMA 只是负责搬数据，真正判断“线路空闲”的，是串口硬件本身。因此在程序设计上，往往是 DMA 开始接收，UART 检测空闲，中断触发后再由软件读取当前 DMA 的接收计数，得出本次实际收到的数据长度。
