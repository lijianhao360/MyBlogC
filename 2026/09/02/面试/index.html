C语言

第一章: C语言基础

1.C语言的基本数据类型有哪些？各自占多少字节？

C语言的基本数据类型包括：

  • char：字符型，1字节
  • short：短整型，2字节
  • int：整型，4字节（32位和64位系统）
  • long：长整型，4字节（32位系统）或8字节（64位系统）
  • long long：长长整型，8字节
  • float：单精度浮点型，4字节
  • double：双精度浮点型，8字节
  • long double：扩展精度浮点型，8/12/16字节（取决于编译器）

注意：具体字节数可能因编译器和平台而异，可使用 sizeof 运算符获取准确值。

面试小记：
指针大小：32位系统指针4字节，64位系统指针8字节，指针大小和类型无关。

2. static 关键字在 C 语言中有哪些作用？

static关键字有三个主要作用：
1.修饰局部变量：改变变量的生命周期，使其在程序整个运行期间都存在，但作用域仍限于函数内部。变量只初始化一次，保留上次调用的值。
2.修饰全局变量：限制变量的作用域，使其只能在当前源文件中访问，其他文件无法通过 extern 引用。
3.修饰函数：限制函数的作用域，使其只能在当前源文件中调用，实现函数的内部链接。

3. const 和 #define 的区别是什么？

主要区别：
1.处理阶段：#define 在预处理阶段进行文本替换；const 在编译阶段处理。
2.类型检查：#define 无类型检查，只是简单替换；const 有类型检查，更安全。
3.调试：#define 定义的宏不便于调试；const 定义的常量可以调试。
4.内存分配：#define 不分配内存（多次使用会有多份拷贝）；const 会分配内存空间。
5.作用域：#define 无作用域限制，直到 #undef 或文件结束；const 遵循作用域规则。
6.指针操作：const 可以定义常量指针；#define 不能。

4. sizeof 和 strlen 有什么区别？

主要区别：

  1. 性质：sizeof 是运算符，在编译时计算；strlen 是库函数，在运行时计算。
  2. 计算内容：sizeof 计算变量或类型所占内存字节数；strlen 计算字符串实际长度（不包括 \0）。
  3. 参数类型：sizeof 可用于任何类型；strlen 只能用于字符串（char*）。
  4. 返回值：sizeof 返回类型为 size_t；strlen 返回字符串长度，类型也是 size_t。

5. 什么是左值（lvalue）和右值（rvalue）？

  • 左值（lvalue）：可以出现在赋值语句左边的表达式，表示一个可寻址的内存位置，可以被赋值。例如：变量、数组元素、解引用的指针等。
  • 右值（rvalue）：只能出现在赋值语句右边的表达式，表示一个临时值或字面量，不能被赋值。例如：常量、表达式结果、临时对象等。

简单判断：能取地址的是左值，不能取地址的是右值。

6. ++i 和 i++ 的区别是什么？

主要区别：

  1. 执行顺序：

    • ++i（前置递增）：先自增，再返回自增后的值
    • i++（后置递增）：先返回当前值，再自增

  2. 返回值：

    • ++i 返回自增后的值（左值）
    • i++ 返回自增前的值（右值）

  3. 效率：++i 通常效率略高（特别是在C++中），因为不需要保存临时副本。

7. break 和 continue 的区别是什么？

  • break：立即终止整个循环或 switch 语句，跳出当前循环体，执行循环后的语句。
  • continue：跳过本次循环剩余的语句，直接进入下一次循环的判断。

主要区别：break 是终止循环，continue 是跳过当前迭代继续下一次迭代。

8. 什么是关键字（keyword）？C语言有多少个关键字？

关键字是C语言中预先定义的、具有特殊含义的标识符，不能用作变量名、函数名等。

C语言共有32个关键字（C89/C90标准）：

  • 数据类型：char, short, int, long, float, double, void, signed, unsigned, struct, union, enum
  • 控制语句：if, else, switch, case, default, for, while, do, break, continue, return, goto
  • 存储类型：auto, static, register, extern
  • 其他：sizeof, typedef, const, volatile

C99标准新增：inline, restrict, _Bool, _Complex, _Imaginary

9. 什么是标识符？命名规则是什么？

标识符是用户自定义的名称，用于标识变量、函数、数组、结构体等。

命名规则：

  1. 只能由字母（A-Z, a-z）、数字（0-9）、下划线（_）组成
  2. 必须以字母或下划线开头，不能以数字开头
  3. 区分大小写（name 和 Name 是不同的标识符）
  4. 不能使用关键字
  5. 长度一般不超过31个字符（标准要求至少支持31个有效字符）

命名建议：

  • 使用有意义的名称
  • 变量名用小写或驼峰命名
  • 常量用大写字母和下划线
  • 函数名用动词开头

10. C语言中 switch 语句的执行流程是怎样的？

执行流程：
1.计算 switch 后括号内表达式的值
2.将表达式的值与各个 case 标签的常量值依次比较
3.如果匹配某个 case，则从该 case 开始执行，直到遇到 break 或 switch 结束
4.如果没有匹配的 case，则执行 default 分支（如果有）
5.如果没有 default 且没有匹配的 case，则跳过整个 switch 语句

注意事项：

  • case 后必须是常量表达式，不能是变量
  • 如果不加 break，会发生”case穿透”，继续执行后续 case 的代码
  • default 可以放在任意位置，但习惯放在最后
  • 表达式必须是整型或字符型

11. volatile关键字的作用

  1. volatile 的核心含义：告诉编译器这个变量可能在当前执行流之外被修改，不要按“值不变”去做激进优化
  2. 强制真实访存：每次读、写 volatile 变量时，一般都会生成实际的 load/store，而不是长期缓存在寄存器里反复使用旧值
  3. 典型使用场景：外设寄存器（硬件会改）、中断与主循环共享的标志位、DMA 或多核共享内存
  4. 能解决什么问题：例如主循环里 while (flag == 0) 等待中断置位，若 flag 不加 volatile，编译器可能只读一次就优化成死循环
  5. 不能解决什么问题：volatile 不保证原子性，也不能当锁用；多线程或中断里共享复杂数据，还要配合临界区、互斥锁或原子操作

第二章: 指针相关

1.什么是指针？指针变量和指针有什么区别？

指针是一个特殊的变量，它存储的是另一个变量的内存地址。通过指针可以间接访问和操作内存中的数据。

指针变量和普通变量的区别：

1.存储内容：
a．普通变量：存储实际的数据值
b．指针变量：存储内存地址

2.声明方式：

  • 普通变量：int a = 10;
  • 指针变量：int *p = &a;

3.访问方式：

  • 普通变量：直接访问值
  • 指针变量：通过解引用（*p）访问指向的值

4.大小：

  • 普通变量：取决于数据类型
  • 指针变量：固定大小（32位系统4字节，64位系统8字节）

5.用途：

  • 普通变量：存储数据
  • 指针变量：动态内存管理、数组操作、函数参数传递等

2.什么是野指针？如何避免？

野指针是指向未知或无效内存地址的指针，使用野指针会导致程序崩溃或产生不可预测的行为。

  • 产生野指针的常见情况：
    1.指针未初始化就使用
    2.指针指向的内存已被释放
    3.指针指向的变量已超出作用域
    4.指针运算越界

  • 避免野指针的方法：
    1.初始化指针：声明时初始化为 NULL 或有效地址

2.释放后置空：释放内存后立即将指针设为 NULL

3.使用前检查：使用指针前判断是否为 NULL

1.避免返回局部变量地址：不要返回指向栈上局部变量的指针
2.注意指针运算边界：确保指针运算不越界

3.什么是空指针（NULL pointer）？

空指针是一个特殊的指针值，表示指针不指向任何有效的内存地址。在C语言中用 NULL 表示（通常定义为 (void *)0）。

  • 空指针的特点：
    1.初始化：指针声明后应初始化为 NULL，表示暂不指向任何对象
    2.判断：可以通过 if (p == NULL) 判断指针是否有效
    3.安全性：对空指针解引用会导致段错误，但比野指针更容易调试
    4.释放后赋值：释放内存后应将指针置为 NULL，防止重复释放

4.指针和数组之间有什么关系？

  • 指针和数组的关系：
    1.数组名是常量指针：数组名代表数组首元素的地址，是一个指向数组第一个元素的常量指针

2.可以互换使用：在大多数情况下，数组名和指针可以互换

  • 区别：
  • 数组名是常量，不能修改；指针是变量，可以修改
  • sizeof(arr) 返回整个数组大小；sizeof(p) 返回指针大小
  • 数组在编译时分配内存；指针可以动态分配
  • 作为函数参数：数组作为参数传递时会退化为指针

5.int *p[10] 和 int (*p)[10] 有什么区别?

这是两种完全不同的声明：

  • int *p[10]：
  • 指针数组（指针组成的数字）
  • 是一个包含10个元素的数组，每个元素都是 int* 类型的指针
  • 优先级：[] 高于 *，先与 p 结合
  • 用途：存储多个指针
  • int (*p)[10]：
  • 数组指针（指向数组的指针）
  • 是一个指针，指向包含10个 int 元素的数组
  • 优先级：() 改变优先级，* 先与 p 结合
  • 用途：指向整个数组

记忆技巧：看括号和优先级，[] 优先级高于 *，加括号改变结合顺序。

6.什么是指针数组和数组指针？

  • 指针数组（Array of Pointers）：
  • 本质是数组，数组的每个元素都是指针
  • 声明：int *arr[10];
  • 含义：包含10个 int* 类型指针的数组
  • 数组指针（Pointer to Array）：
  • 本质是指针，指向一个数组
  • 声明：int (*p)[10];
  • 含义：指向包含10个 int 元素的数组的指针
  • 区别总结：
  • 指针数组：存储多个指针的数组
  • 数组指针：指向数组的单个指针

8.指针运算的规则是什么？

指针运算的类型：

指针加减整数：

  • p + n：指针向后移动 n 个元素（移动 n * sizeof(类型) 字节）
  • p - n：指针向前移动 n 个元素

指针自增自减：

  • p++、++p：指向下一个元素
  • p--、--p：指向上一个元素

指针相减：

  • 两个同类型指针相减，得到它们之间的元素个数

指针比较：

  • 通常用于判断指针是否在同一数组内

注意事项：

  • 指针只能与整数进行加减运算
  • 两个指针不能相加或相乘
  • 只有指向同一数组的指针相减才有意义
  • 指针运算要注意边界，避免越界

2.一维数组和二维数组在内存中是如何存储的？

  • 一维数组：
    在内存中连续存储，按照声明顺序依次排列。

  • 地址计算: &arr[i] = arr的首地址 + i * sizeof(int)

    在内存中也是连续存储的，按照行优先的方式存储（先存储第一行，再存储第二行）。

访问方式：

  • arr[i][j] 等价于 ((arr + i) + j) 或 *(&arr[0][0] + i * 列数 + j)
  • 地址计算: &arr[i][j] = 首地址 + (i * 列数 + j) * sizeof(int)

理解方式：

  • arr 是指向第一行的指针（类型为 int (*)[4]）
  • arr[i] 是指向第 i 行第一个元素的指针（类型为 int *）
  • arr[i][j] 是具体的元素值

3.字符串在 C 语言中的本质是什么？为什么字符串需要以 \0 结尾？

C语言中的字符串本质是一个字符数组，以空字符 \0（ASCII码为0）作为结束标志。

为什么需要 \0 结尾：
C语言没有专门的字符串类型，无法直接获取字符串长度，必须通过结束标志来判断字符串的结束位置。

作用：

  • 标识字符串的结束位置
  • 让字符串处理函数知道何时停止
  • 防止读取越界

注意事项：

  • 字符串字面量自动添加 \0
  • 手动创建字符数组时要预留 \0 的空间
  • 如果缺少 \0，字符串函数会继续读取内存，导致未定义行为

4.char str[] = “hello” 和 char *str = “hello” 有什么区别?

这是两种完全不同的声明方式：

char str[] = “hello”：

  • 定义了一个字符数组，内容是”hello”
  • 数组存储在栈上（如果是局部变量）或数据段（如果是全局变量）
  • 内容可以修改
  • sizeof(str) 返回 6（包括 \0）
  • 数组名是常量，不能修改指向

*char str = “hello”：

  • 定义了一个指针，指向字符串常量
  • 字符串常量存储在只读数据段（常量区）
  • 内容不能修改（修改会导致段错误）
  • sizeof(str) 返回指针大小（4或8字节）
  • 指针可以修改指向

对比总结：

特性 char str[] char *str

可修改性 可修改内容 不可修改内容
指针/数组 数组（常量） 指针（变量）
sizeof 数组大小 指针大小

7.什么是数组越界？会导致什么问题？

数组越界是指访问数组时，索引超出了数组的有效范围（小于0或大于等于数组长度）。

  • 会导致的问题：
    读越界：
  • 读取到未知的内存数据（垃圾值）
  • 可能读取到其他变量的数据
  • 程序可能正常运行，但结果不可预测

写越界：

  • 破坏相邻内存的数据
  • 覆盖其他变量的值
  • 破坏程序的栈帧，导致程序崩溃
  • 可能导致安全漏洞（缓冲区溢出攻击）

危险性：

  • C语言不会自动检查数组边界
  • 编译器通常不会报错
  • 运行时可能不会立即崩溃，难以调试
  • 是常见的安全漏洞来源

如何避免：

  • 使用循环时检查索引范围
  • 使用 sizeof(arr) / sizeof(arr[0]) 获取数组长度
  • 使用断言或条件判断
  • 使用静态分析工具检测

第四章: 内存管理

1.C语言中常见的内存区域有哪些？

C语言程序的内存布局通常分为以下几个区域（从低地址到高地址）：
代码段（Text Segment）：

  • 存储程序的机器码（可执行指令）
  • 只读区域，防止程序被意外修改
  • 所有函数的代码都存储在这里

数据段（Data Segment）：

  • 已初始化数据段：存储已初始化的全局变量和静态变量
  • 未初始化数据段（BSS段）：存储未初始化的全局变量和静态变量

堆（Heap）：

  • 用于动态内存分配
  • 由程序员手动管理（malloc/free）
  • 从低地址向高地址增长
  • 生命周期由程序员控制

栈（Stack）：

  • 存储局部变量、函数参数、返回地址等
  • 由编译器自动管理
  • 从高地址向低地址增长
  • 函数调用时分配，函数返回时释放

常量区（Constant/Read-Only Data）：

  • 存储字符串常量和const修饰的全局变量

2.栈（stack）和堆（heap）的区别是什么？

管理方式：

  • 栈：由编译器自动管理，无需手动干预
  • 堆：由程序员手动管理，需要malloc/free

分配速度：

  • 栈：速度快，只需移动栈指针
  • 堆：速度慢，需要复杂的内存管理算法

空间大小：

  • 栈：空间较小，通常1-8MB（可通过系统设置调整）
  • 堆：空间较大，受限于系统虚拟内存

生命周期：

  • 栈：函数调用时分配，函数返回时自动释放
  • 堆：程序员控制，从malloc到free

增长方向：

  • 栈：从高地址向低地址增长
  • 堆：从低地址向高地址增长

内存碎片：

  • 栈：不会产生碎片，连续分配
  • 堆：频繁分配释放会产生内存碎片

访问效率：

  • 栈：访问速度快，有CPU缓存支持
  • 堆：访问速度相对较慢

溢出问题：

  • 栈：栈溢出（Stack Overflow），如递归过深
  • 堆：堆溢出较少见，但可能内存耗尽

3.malloc、calloc、realloc 和 free 的作用是什么？

  • malloc (memory allocation)：
    分配指定字节数的内存，不初始化。
  • calloc (contiguous allocation)：
    分配指定数量和大小的内存，并初始化为0。
  • realloc (re-allocation)：
    重新调整已分配内存的大小。

realloc的行为：

  • 如果新大小更大，可能在原地扩展或分配新内存并复制数据
  • 如果新大小更小，截断多余部分
  • 如果ptr为NULL，等同于malloc
  • 如果new_size为0，等同于free（但不推荐）
  • free：
    释放动态分配的内存。

注意事项：

  • 只能释放malloc/calloc/realloc分配的内存
  • 不能释放栈内存
  • 不能重复释放同一块内存
  • 释放后应将指针置为NULL

6.volatile 使用

  • 作用
    1.易变性：修饰的变量数据很容易被外部改变。
    2.禁止编译器优化内存读取，保证内存可见性
    定义为volatile的变量，每次都直接从内存读取，不会读取寄存器缓存里的副本。
    3.保证执行顺序性，多用于多线程场景。

  • 使用场景
    1.多线程：全局共享变量、频繁被多个线程修改，加volatile，强制每次访问读内存，避免读取寄存器缓存旧值。
    2.嵌入式开发：硬件寄存器、中断服务函数中会修改的变量，用volatile修饰。

  • 重要考点：volatile 不能保证原子性

    易错坑：volatile只解决可见性，不保证原子操作，不能替代互斥锁。

  • 底层实现
    依靠lock汇编指令：lock锁住操作的缓存行；先把当前处理器缓存写回内存，该写入动作会让其他CPU核对应的缓存失效，阻止指令重排越过内存屏障。

  • 一句话背诵版（面试简答）
    volatile用来告诉编译器变量是易变的，禁止编译器将变量缓存到寄存器，每次读写直接访问内存，保证内存可见性、防止指令重排；但是volatile不能保证操作原子性，常用于嵌入式硬件寄存器和多线程共享变量。

原子操作：不可被拆分的操作，一旦开始执行，要么完整做完，要么完全不执行，执行中途不会被线程 / 中断打断。

8.四种类型强转、dynamic_cast底层实现、类型强转失败会怎么样

  • static_cast 静态类型强转
  • 用途1：执行那些基本的内置数据类型转换
  • 用途2：用于指针之间的类型转换
    • 上行转换：子类向基类转换
    • 下行转换：基类向子类转换
  • const_cast 常量转换
    主角2：const_cast
  • 用途：用于去除变量的 const 或者 volatile 属性
  • 这个其实没啥可以聊的地方，只要记住，这玩意的功能只有这个就是了，不能用于除此之外的类型转换。顺带一提，虽然这玩意对于我们处理 const 变量时能方便不少，毕竟你没法隐式的转换 const 变量，但是……感觉好不安全，有丢让 const 的安全性打折扣
  • reinterpret_cast 重新解释转换
    主角3：reinterpret_cast
  • 用途：这个关键字就很简单粗暴，无论其是否相关，都直接重新解释
  • 注意事项
    • type-id和expression中必须有一个是指针或引用类型（可以两个都是指针或引用，指针引用在一定场景下可以混用），但是建议不要这样做，编译器也会给出相应的警告。
    • reinterpret_cast的第一种用途是改变指针或引用的类型
    • reinterpret_cast的第二种用途是将指针或引用转换为一个整型，这个整型必须与当前系统指针占的字节数一致
    • reinterpret_cast的第三种用途是将一个整型转换为指针或引用类型
    • 可以先使用reinterpret_cast把一个指针转换成一个整数，再把该整数转换成原类型的指针，还可以得到原先的指针值（由于这个过程中type-id和expression始终有一个参数是整形，所以另一个必须是指针或引用，并且整形所占字节数必须与当前系统环境下指针占的字节数一致）
    • 使用reinterpret_cast强制转换过程仅仅只是比特位的拷贝，和C风格极其相似（但是reinterpret_cast不是全能转换，详见第1点），实际上reinterpret_cast的出现就是为了让编译器强制接受static_cast不允许的类型转换，因此使用的时候要谨而慎之
    • reinterpret_cast同样也不能转换掉expression的const或volatile属性。
  • dynamic_cast 动态转换
    主角4：dynamic_cast
  • 用途：这个关键字的出现就是为了解决static_cast无法进行类型转换之间的类型检查的问题，且要注意的一点是，此关键字要求类的转换拥有多态的特性，说的更具体一些，需要类中需要虚函数的存在，因为唯有如此，该关键字才认为此次转换时拥有意义的。否则，毫无价值。
  • dynamic_cast是运行时处理的，运行时会进行类型检查（这点和static_cast差异较大）
  • dynamic_cast不能用于内置基本数据类型的强制转换，并且dynamic_cast只能对指针或引用进行强制转换
  • dynamic_cast如果转换成功的话返回的是指向类的指针或引用，转换失败的话则会返回nullptr
  • 使用dynamic_cast进行上行转换时，与static_cast的效果是完全一样的
  • 使用dynamic_cast进行下行转换时，dynamic_cast具有类型检查的功能，比static_cast更安全。并且这种情况下dynamic_cast会要求进行转换的类必须具有多态性（即具有虚表，直白来说就是有虚函数或虚继承的类），否则编译不通过
  • 需要有虚表的原因：类中存在虚表，就说明它有想要让基类指针或引用指向派生类对象的情况，dynamic_cast认为此时转换才有意义（事实也确实如此）。而且dynamic_cast运行时的类型检查需要有运行时类型信息，这个信息是存储在类的虚表中的
  • 在C++中，编译期的类型转换有可能会在运行时出现错误，特别是涉及到类对象的指针或引用操作时，更容易产生错误。dynamic_cast则可以在运行期对可能产生问题的类型转换进行测试
  • 汇总考点笔记
  1. static_cast：编译期转换，支持基础类型、继承上下行转换；下行转换不做运行时检查，不安全。
  2. const_cast：只用来增删const/volatile属性，不能做类型转换。
  3. reinterpret_cast：粗暴按二进制比特重新解释，几乎不做检查，风险极高。
  4. dynamic_cast：运行时类型检查RTTI，要求类必须有虚函数（多态）；
    • 指针转换失败：返回nullptr
    • 引用转换失败：抛出bad_cast异常

09 程序从main开始执行么

和 attribute 中的constructor和destructor有关，有点类似C++的构造函数和析构函数
attribute主要可以设置函数属性、变量属性和类型属性，主要是函数属性（设置为constructor 在main函数之前执行、destructor 在main函数之后执行）

  • 考点笔记
  1. 结论：程序不是从main最先开始执行。__attribute__((constructor))修饰的函数，在main之前自动运行；__attribute__((destructor))修饰的函数，main结束、程序退出前自动运行（GCC扩展语法）。
  2. 适用：GCC编译器扩展，不是C语言标准。
  3. 用途：多用于全局资源预加载、初始化，程序退出前释放资源。
  4. 执行顺序：constructor函数 → main函数 → destructor函数。

一句话背诵：GCC的__attribute__((constructor))函数在main之前执行，destructor在main结束后执行，所以程序入口执行点早于main。

10 delete和delete[]的区别

如果是针对自定义的类对象指针的内存开辟和释放（类中没有内存的开辟时），单个对象的内存的开辟必须用delete来释放，多个对象内存的开辟必须用delete[]来释放。

在C++中，delete 和 delete[] 都是用于释放动态分配的内存的操作符。它们之间的区别在于：

  1. 使用方式：delete 用于释放单个对象的内存，而 delete[] 用于释放数组对象的内存。也就是说，如果通过 new 分配了单个对象的内存，则应该使用 delete 将其释放；如果通过 new[] 分配了数组对象的内存，则应该使用 delete[] 将其释放。
  2. 操作对象的数量：delete 操作符只能释放一个对象的内存，而 delete[] 操作符可以释放一个数组对象的内存，且会调用数组中每个元素的析构函数。
  3. 内存释放的方式：delete 只会释放分配的单个对象的内存，而 delete[] 则会释放分配的数组的内存以及数组中所有元素的内存。这也就意味着，如果使用 delete 释放数组对象的内存，只有第一个元素的内存被释放，其他元素的内存则不会被释放，从而导致内存泄漏。

因此，当需要释放动态分配的数组对象的内存时，必须使用 delete[] 操作符，而不能使用 delete 操作符。反之，当需要释放动态分配的单个对象的内存时，则应该使用 delete 操作符。

总之，delete 和 delete[] 的区别在于操作对象的数量和内存释放的方式。在使用过程中，需要根据具体的情况选择使用哪个操作符，以确保内存的正确释放。

  • 考点补充笔记

    底层原理：new[]会额外记录数组元素个数，delete[]读取这个数字，循环调用每一个对象的析构函数；普通delete只调用一次析构函数。
    重要规则：new 匹配 delete；new[] 匹配 delete[]，不能混用，混用属于未定义行为。
