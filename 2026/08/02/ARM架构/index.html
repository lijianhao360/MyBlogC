ARM架构

发表于 2026-08-02 更新于 2026-09-02 分类于 基础 阅读次数：

第一章: 计算机架构导论

1.架构趋势

1.1 计算机架构概述

  • 1.处理器发展趋势
  • 1.处理器在数据中心与嵌入式系统中的应用
  • 两大典型应用领域与差异
    1. 数据中心场景（例如Google数据中心）
    • 硬件：采用高性能处理器，算力要求高
    • 软件：运行服务器操作系统，执行服务器专用业务程序
    1. 嵌入式MCU场景（例如Cortex‑M3）
    • 硬件：典型配置：16KB Flash + 4KB RAM，算力需求低
    • 软件：可跑裸机程序（Bare‑metal，直接写业务函数，无需操作系统），也可运行轻量级嵌入式操作系统

总结：两类处理器硬件性能、软件特性差别很大，但本质都是依靠CPU提供算力来完成数据处理任务。

  • 2.计算机的发展历程
  • 历史演进
    • 第一代电子计算机：EDSAC（1930‑1940年代）
      • 实物体积十分庞大，如今博物馆存有复刻版本。
    • 现代嵌入式设备：micro:bit开发板，搭载 ARM Cortex‑M0 处理器
      • 板载USB接口，电脑网页端完成图形化编程，编译后烧录到芯片。
      • 基础功能：控制板载LED；可通过扩展槽外接LCD屏幕，实现图像显示。
    • 发展特点：从体积庞大的老式计算机，演变为微型处理器、SoC芯片，硬件发展速度极快。
  • 技术突破与现代处理器设计指标

    相比早期计算机，现代计算机在速度、功耗、可靠性、成本上实现数量级提升，同时新增安全性设计要求，现代处理器的设计要求：

    1. 速度：处理器运算性能，程序运行要快。
    2. 功耗：芯片面积越小，功耗越低，如Cortex‑M0面积小、功耗低、成本低廉。
    3. 可靠性：抗干扰能力。自然界电磁、辐射干扰可能造成比特位翻转，导致程序出错；处理器设计需要应对这类硬件故障。
    4. 成本：控制芯片价格。
    5. 安全性：具备防攻击能力，防止黑客窃取CPU内部加密密钥、破解指令，保护加密解密相关数据。
    6. **设计平衡：**需要在性能、功耗、可靠性和安全性之间取得平衡

1.2 计算机架构的层次

  • 1.三层抽象（Levels of Abstraction）
    1.架构层（Architecture）
  • ARM定义架构标准，例如 ARMv7、ARMv8‑A / v8‑R / v8‑M、ARMv9。
  • 产出架构文档，复杂架构文档可达数千页，可在ARM官网下载。
  • 偏向软件视角：规定指令集、CPU对外行为，是给开发者使用的一套接口规范。

2.微架构层（Microarchitecture）

  • 属于CPU内部逻辑设计，架构标准不做规定。
  • 内容包含：流水线级数（3~10级）、分支预测、内存管理单元等内部设计。
  • 同一种架构可以拥有多种不同微架构，例如Cortex‑A72、A73、A55，流水线stage各不相同。

3.硬件实现层（Implementation）

  • 在微架构基础上完成的最终处理器型号，物理芯片逻辑设计。
  • 例：Cortex‑A72、Cortex‑A73，是ARMv8‑A架构下的具体处理器实现。

implementation defined（实现定义）
架构文档里常见术语：部分行为架构不做强制规定，具体表现由实际处理器硬件实现决定。

小结：架构定接口，微架构定内部逻辑，实现对应真实芯片型号。

1.3 计算机架构的定义

ARM架构文档可在官网下载，文档面向研发可查阅，但并非商业完全开源：仅可用于研究；如果要商业化生产兼容架构的处理器，必须向ARM支付架构授权费用。

  • 1.架构定义的五大核心要素
    1.指令集 Instruction set
  • 规定处理器全部指令、指令编码格式、指令功能。
  • ARM架构文档公开指令相关资料，可供研究，但商业化使用需要授权。

2.内存模型 Memory model

  • 管理整个地址空间，区分不同内存类型（SRAM、外设寄存器等）。
  • 定义内存保护机制：实现软件之间隔离，例如操作系统与应用程序隔离。
  • 管理内存的读写权限、访问规则。

3.编程模型 Program model

  • 软件视角，规定寄存器的使用规范
    • 通用寄存器：M系列 R0‑R1；ARMv8‑A X0~X30等64位通用寄存器
    • 特殊寄存器：堆栈指针SP、各类系统控制寄存器
  • 定义处理器执行级别/运行模式
    • ARMv8‑A：EL0 ~ EL3 不同执行等级
    • ARMv7‑A：用户模式、特权模式、中断模式、快速中断模式、管理模式等
  • 规定不同软件（应用、操作系统、中断服务程序）应当运行在哪种处理器模式。

4.异常处理 Exception handling

  • 定义异常发生时，处理器进入异常、退出异常完整流程与硬件行为。
  • 偏向软件规范。

5.调试支持 Debug

  • 标准化调试架构，规定断点、观察点等调试事件、调试相关寄存器。
  • 统一标准保证调试工具可以适配处理器；处理器和调试器遵循同一套标准，才能正常调试。

小结：架构全部偏向软件接口规范，用来约束软件如何和CPU交互。

  • 2.计算机架构与处理器设计的关系

    Computer‑Architecture 是架构层、微架构层、硬件实现层三者的综合概念，处理器设计需要同时兼顾软件规范、流水线、分支预测、内存管理等全部内容。

  • 1.处理器设计的整体流程与设计考量
    1.第一步：选定架构标准
    设计处理器首先确定遵循哪一套ARM架构，例如 ARMv8‑A / ARMv8‑M。

2.第二步：微架构设计，重点选择流水线级数

  • 流水线级数越多，硬件设计复杂度越高，功耗也随之增大。
  • 流水线级数不能盲目做大，需要结合目标市场、应用场景做权衡：
    • 根据市场对性能的要求，选择2级、3级、7级、8级等不同流水线。
    • 面向手机、嵌入式、服务器等不同场景，需要匹配不同微架构。

3.核心目标：结合现有半导体工艺，设计出匹配市场需求的处理器

能效比概念（手机处理器的核心指标）

  • 能效比：单位功耗下可以达到的性能（每瓦性能）

  • 手机芯片迭代的核心追求：提升能效比，做到性能提升的同时控制甚至降低功耗。

  • 设计时综合权衡三大指标：功耗、芯片面积、运算性能。

  • 2.计算机架构随应用需求持续演变
    架构不是一成不变，会跟随用户场景（use case）迭代更新：

  1. 2015年之前：AI业务需求低，处理器架构基本不考虑AI算力。
  2. 2015年之后：AI应用爆发，处理器设计必须加入AI相关能力。
  3. ARMv9架构：新增AI加速能力、增强安全特性，用来适配新兴业务需求。

设计哲学：处理器架构必须持续演进，来不断适配变化的应用场景与用户需求。

1.4 计算机架构领域

  • 1.架构设计的层级与影响因素
  • 层级关系：完整技术栈从上至下：应用层 → 操作系统 → 编程语言/编译器 → 微架构 → 硬件实现 → 制造工艺。
  • 动态演变：各层需求、约束会随时间发生变化，架构设计需要具备前瞻性。
  • 商业考量：架构演进要兼顾商业诉求，尽可能降低生态破坏成本，保障软件兼容性。
  • 2.市场对架构变化的影响
  • 决定性作用：市场需求直接驱动架构迭代方向。
  • 应用场景差异：移动设备、服务器、嵌入式等不同领域，对性能、功耗、面积、成本指标要求不一样。
  • 生态影响：架构设计必须考量现有软件生态的迁移成本。
  • 3.工艺发展对CPU性能的影响
  • 工艺进步：半导体制程迭代，能够改善晶体管本身性能，助力CPU性能提升。
  • 微架构优化：流水线等微架构设计，必须结合当下工艺的特性开展设计。
  • 协同设计：处理器设计要跟工艺发展同步，避免基于落后工艺做设计。

4.处理器设计考虑未来应用与生态系统

  • 前瞻性设计：需要预判未来数年业务负载特征。
  • 扩展能力：架构预留余量，能够适配新兴业务负载。
  • 生态兼容：保证新架构可以适配后续软件生态的演进。
  • 5.不同市场的性能、面积与成本需求
  • 移动设备：重点追求能效比，控制芯片成本。
  • 服务器：追求绝对性能，看重多核扩展能力。
  • 嵌入式：强调确定性、实时响应。
  • 安全领域：重点做抗攻击设计、高可靠性。
  • 6.硬件实践与微架构的实验验证
  • 验证必要性：硬件流片之后出现bug，不能像软件一样打补丁修复，损失巨大。
  • 实验方法论：依靠实验、基准跑分，对比评估多种微架构方案优劣。
  • 7.Cache结构与设计考量
  • 层级结构：L1、L2、L3三级缓存，各项参数都需要权衡取舍。
  • 相联度选择：支持2路、4路、8路相联，相联度影响缓存命中率。
  • 性能拐点：相联度提升到一定程度，性能收益不再明显。
  • 面积代价：提高相联度会显著增大芯片面积。
  • 定制化设计：针对目标软件负载去调优缓存参数。

1.5 处理器六大设计目标

  • 1.功能性

  • 验证挑战：处理器验证复杂度远高于软件，需要覆盖海量、多样的指令组合场景。

  • 纠错成本：硬件重大bug会直接造成整款产品失败，功能验证占设计成本很高。

  • 测试要求：芯片流片完成后，依旧需要复杂完备的测试流程。

  • 2.性能

  • 场景依赖：没有统一的性能标准，不同应用场景侧重点完全不同。

  • 评估方法：依靠基准测试（跑分）量化性能。

  • 市场差异：手机、服务器对性能指标要求各不相同。

  • 3.功耗(Power)

  • 关键约束：现代处理器核心设计约束条件。

  • 用户体验：直接决定设备续航，例如手机待机时长。

  • 系统影响：处理器功耗是整个SoC功耗的基线。

  • 4.安全(Security)

  • 威胁防护：抵御恶意软件窃取敏感数据，例如密钥、指纹、人脸信息。

  • 软件安全：ARMv9相比ARMv8提升安全等级；TrustZone提供软件隔离运行环境。

  • 硬件安全：银行卡、身份证芯片需要抵御物理旁路攻击。

  • 安全分级：不同业务场景匹配不同安全防护等级。

  • 5.成本

  • 多维构成：包含设计复杂度、芯片面积、封装等多项开销。

  • 市场定位：嵌入式、消费电子、服务器对成本敏感度差异很大。

  • 平衡艺术：在性能、功耗、安全之间寻找成本最优解。

  • 6.可靠性

  • 故障处理：能够检测、容忍运行时故障，例如宇宙辐射引发比特位翻转。

  • 纠错技术：ECC内存，支持比特错误检测与纠错。

  • 耐久设计：处理存储器单元长期使用损坏失效问题。

  • 关键应用：工业控制、航空航天等高可靠场景刚需。

1.6 ARM目标市场与处理器分类

  • 1.处理器设计的权衡因素
  • 多维优化：同时权衡功耗、成本、芯片面积、性能、安全、可靠性多项指标。
  • 市场细分：不同场景，各项指标权重不一样。
  • 定制化设计：不存在通用最优方案，针对目标市场做定向优化。
  • 2.ARM主流处理器系列

  • Cortex‑A 系列

  • 定位：高性能应用处理器

  • 特点：可以运行复杂操作系统，Android、Linux。

  • 典型：A73/A75/A76（性能大核）；A55/A53（能效小核）；大小核架构。

  • 应用：手机、电视盒子、监控设备。

  • Cortex‑R 系列

  • 定位：高实时性控制器

  • 特点：执行时间确定性、中断延迟可控；支持ECC错误检测。

  • 应用：硬盘控制器、4G/5G基带、Wi‑Fi、网络控制器。

  • Cortex‑M 系列

  • 定位：超低功耗嵌入式MCU

  • 特点：单位面积功耗极低、成本低廉。

  • 应用：手环、智能手表、家电、玩具。

  • Neoverse 系列

  • 定位：服务器、数据中心处理器

  • 特点：强多核可扩展，支持大规模核数（最高可达上百核），追求高吞吐。

  • 应用：云端服务器、边缘计算。

  • 3.智能手机内部异构处理器分工

  • 应用处理器 AP

  • 主核心：Cortex‑A系列，运行安卓系统、上层应用。

  • 辅助内核：Cortex‑M，负责电源管理、系统控制等后台任务。

  • 通信模块

  • 基带：Cortex‑R系列处理4G/5G通信协议栈，满足实时、确定性要求。

  • 短距连接：Cortex‑M负责蓝牙、Wi‑Fi。

  • 传感器子系统
  • 摄像头、GPS等外设，数据量不大，使用 Cortex‑M完成数据处理。

异构优势：多种ARM处理器协同工作，兼顾性能、实时性、功耗，实现整体能效最优。

2.性能进化

1.过去性能发展

  • **工艺突破：**1985年首次实现完整微处理器单芯片集成，此后晶体管尺寸持续缩小（从微米级发展到3nm工艺）
  • **性能增速：**1985-2005年间SPEC基准测试显示桌面/服务器处理器性能年增长达52%
  • **集成优势：**工艺进步带来芯片面积缩小、功耗降低，使更多功能模块可集成到单一芯片中

2.时钟频率

● 关键贡献：1985-2002年间处理器性能提升800倍，其中时钟频率改善贡献约100倍（占总提升1/8）
● 提升因素：
○ 晶体管速度提升带来10倍增益 ○ 流水线和电路级优化带来额外10倍增益
● 现状转变：2002年后频率提升放缓，转向多核架构发展

  • 1）处理器性能衡量

  • 核心公式：Time = 指令数 * CPI * 时钟周期
    （CPI=Clocks Per Instruction）

  • IPC概念：IPC = 1/CPI，表示每时钟周期执行的指令数

  • 执行指令数

    • 评估标准：通过SPEC等基准测试程序测量实际软件执行效率
    • 全面考量：性能评估需综合指令吞吐量、执行效率等多维度指标

  • 时钟周期

    • 工艺影响：晶体管速度提升直接缩短时钟周期
    • 频率瓶颈：工艺节点接近物理极限后频率提升难度增

补充：
Time：程序执行总时间
CPI：每条指令需要的时钟周期数
IPC：每个时钟周期能完成多少条指令

  • 2）时钟每条指令
  • 早期限制：晶体管数量不足导致CPI>>1（单指令需多周期完成）
  • 现代目标：通过架构优化逼近CPI=1的理想状态
  • **设计矛盾：**高频设计（>3GHz）与低CPI存在天然矛盾，需复杂技术平衡
  • 3）减小CPI
  • 关键技术：
    • 指令级并行（ILP）：通过超标量架构实现多指令同时执行
    • 流水线优化：减少流水线停顿（stall）导致的周期浪费
  • 实现代价：需要额外晶体管资源（面积）和功耗开销
  • 4）流水线

3.IPC和指令数

  • 1）性能提升概述
  • 800倍提升分解：1985-2002年间处理器性能提升800倍，其中约100倍来自时钟频率提升，剩余约8倍来自指令数减少、编译器优化和IPC提升
  • 基准测试：使用Specint2000作为性能评估基准，图表显示性能（每MHz）随时间的变化趋势
  • 2）指令数减少的影响
  • 指令集演进：处理器架构发展引入新指令，相同代码编译后指令数减少
  • 具体表现：现代CPU执行相同代码时所需汇编指令数量比早期处理器更少
  • 工艺影响：先进工艺节点使标准单元库延迟时间缩短，寄存器间时钟周期减小
  • 3）编译器优化的作用
  • 优化能力：现代编译器能根据CPU特性和功能优化C/C++代码
  • 协同设计：处理器架构与编译器协同优化，共同提升执行效率
  • 4）IPC提升的意义与实现
  • IPC定义：每周期执行指令数（Instructions Per Cycle）提升意味着CPI（Cycles Per Instruction）降低
  • 实现方式：通过微架构改进增加单周期内并行执行的指令数量
  • 5）关键路径的减小方法
  • 流水线技术：采用多级流水线（从2-3级发展到7-8级甚至几十级），通过寄存器切断长组合逻辑路径
  • 工艺进步：更先进工艺节点缩短晶体管延迟时间
  • 设计优化：复杂逻辑细化为更小单元，关键路径时间长度显著减小（1985-2002年间）

4.处理器发展趋势

  • 1）ARM处理器性能趋势
  • 性能提升：
  • 2009年Cortex-A8：单核800MHz
  • 2016年Cortex-A72：单核2.5GHz（14/16nm工艺）
  • 性能提升倍数：浮点运算12倍，整型运算14倍，内存访问16倍
  • 功耗优化：
  • 16nm A72相比28nm A15功耗降低75%
  • big.LITTLE架构（A72+A53组合）进一步降低功耗40-60%
  • 架构创新：
  • 增加缓存容量和改进缓存管理
  • 内存速度提升避免CPU流水线阻塞
  • 工艺进步（28nm→20nm→16nm）同时提升性能和能效
