Day-01 初识 STM32

1.STM32概述

  • STM32是ST公司基于ARM Cortex‑M内核开发的32位微控制器
  • STM32常应用在嵌入式领域，如智能车、无人机、机器人、无线通信、物联网、工业控制、娱乐电子产品等
  • STM32功能强大、性能优异、片上资源丰富、功耗低，是一款经典的嵌入式微控制器
  • ARM:
  • ARM既指ARM公司，也指ARM处理器内核
  • ARM公司是全球领先的半导体知识产权（IP）提供商，全世界超过95%的智能手机和平板电脑都采用ARM架构
  • ARM公司设计ARM内核，半导体厂商完善内核周边电路并生产芯片

2.GPIO 初始化,新建工程

  • 代码功能解析
    这段代码是基于STM32F10x系列单片机的最基础GPIO初始化代码，核心功能是配置GPIOC的第13引脚为推挽输出模式，并将该引脚置低电平

作为嵌入式新手，这个问题核心是理解十六进制与二进制的转换，以及寄存器位编号的规则，用最基础的方式一步步拆解，保证能看懂。

  • 一、先搞懂：0x00000010的二进制为什么是0001 0000？
    首先明确两个基础规则：
  1. 十六进制（0x开头）转二进制：1个十六进制位 = 4个二进制位（因为16=2⁴）；
  2. 数字的“有效位”和“补零”：0x00000010 是32位寄存器的写法（STM32的寄存器大多是32位），但核心有效位是最后两位10，前面的000000都是补零。
  • 分步转换：
    十六进制数 拆分（按4位一组） 对应二进制 简化后（只看有效位）
    0x00000010 00 00 00 10 0000 0000 0000 0000 0000 0000 0001 0000 0001 0000（最后8位）
  • 关键：0x10（十六进制）= 16（十进制）= 2⁴（2的4次方），而二进制中“2的n次方”对应的就是第n位为1，其余位为0（比如2⁰=1 → 第0位1，2¹=2 → 第1位1，以此类推）。
  • 所以0x10=16=2⁴ → 二进制只有第4位是1，其余位是0，也就是0001 0000（8位视角）。

  • 二、再理解：为什么对应APB2ENR寄存器的第4位（IOPCEN位）？
    STM32的寄存器是32位，但我们关注的是低16位（APB2ENR的有效位集中在低16位），寄存器的位编号遵循“从右往左，从0开始数”的规则，这是所有单片机/处理器的通用规则。

  • 直观举例（APB2ENR寄存器低8位）：

    位编号 7 6 5 4 3 2 1 0
    名称 - - - IOPCEN IOPBEN IOPAEN - -
    二进制 0 0 0 1 0 0 0 0
    对应值 0×80 0×40 0×20 0×10 0×08 0×04 0×02 0×01
  • 你代码中的0x00000010，就是把第4位（IOPCEN位）置1，其余位置0；
  • IOPCEN是“IO Port C Enable”的缩写，翻译过来就是“GPIOC端口使能”——置1就代表开启GPIOC的时钟。
  • 三、新手易踩坑的补充说明

  1. 位编号“从0开始”是关键：
    很多新手会误以为0x10对应第16位（因为10是十六进制），或第10位（因为数字是10），核心错误是忘了“位编号从0开始”。
    记住：2ⁿ对应第n位，0x10=2⁴ → 第4位。

  2. 为什么原代码写0x00000010而不是0x10？
    这是32位寄存器的“完整写法”，前面的0是补位，让代码更清晰（明确是32位值），但实际效果和0x10完全一样——编译器会自动识别为32位。

  3. 对比理解（更易记）：

    • 0x01 → 2⁰ → 第0位（IOPAEN，GPIOA时钟）；
    • 0x04 → 2² → 第2位（IOPBEN，GPIOB时钟）；
    • 0x10 → 2⁴ → 第4位（IOPCEN，GPIOC时钟）。
  • 总结
  1. 0x00000010的核心是0x10，转换为十进制是16=2⁴，因此二进制只有第4位为1，表现为0001 0000；
  2. 寄存器位编号“从右往左、从0开始”，第4位正好是APB2ENR的IOPCEN位（GPIOC时钟使能位）；
  3. 本质是通过“置1第4位”来开启GPIOC的时钟，这是操作GPIOC的前提。

3.STM32标准库函数（非直接操作寄存器）来配置GPIOC13引脚为推挽输出并置低电平

  • 总结
  1. 核心逻辑：标准库方式开启GPIOC时钟 → 配置PC13为50MHz推挽输出 → 置PC13低电平 → 死循环保持状态；
  2. 关键优势：标准库函数（如RCC_APB2PeriphClockCmd、GPIO_Init）封装了底层寄存器操作，无需记忆十六进制值，代码可读性和可移植性更强；
  3. 核心函数：GPIO_ResetBits（置低）/GPIO_SetBits（置高）是标准库操作GPIO电平的专用函数，比直接写ODR寄存器更安全。

  • 完整新建工程步骤总结（补充细节版）
  • 1. 建立工程文件夹，Keil中新建工程，选择型号
  • 操作细节：
    1. 在电脑非系统盘新建总工程文件夹（如STM32_Project），禁用中文路径/特殊字符（避免Keil编译/下载报错）。
    2. 打开Keil，点击Project → New μVision Project，选择总文件夹，命名工程（如Project）并保存。
    3. 在Select Device for Target窗口，依次展开STMicroelectronics → STM32F103，选择与开发板匹配的芯片型号（如STM32F103C8），点击OK。
    4. 弹出Manage Run-Time Environment窗口，直接点击Cancel（标准库工程无需启用RTE）。
  • 核心作用：完成工程基础框架创建，指定目标芯片（决定后续Flash算法、寄存器映射）。
  • 新手避坑：芯片型号必须与实物一致（如C8T6选STM32F103C8，ZET6选STM32F103ZE），否则会出现烧录失败/功能异常。
  • 2. 工程文件夹里建立Start、Library、User等文件夹，复制固件库里面的文件到工程文件夹
  • 操作细节：
    1. 在总工程文件夹内新建3个功能子文件夹：
      • Start：存放芯片启动文件（汇编文件，决定程序入口）；
      • Library：存放标准库驱动源码/头文件；
      • User：存放用户自定义代码（如main.c）。
    2. 从STM32F10x标准固件库（V3.5.0）中复制对应文件：
      • Start文件夹：复制Libraries\CMSIS\CM3\DeviceSupport\ST\STM32F10x\startup\arm下的启动文件（中容量芯片如C8T6选startup_stm32f10x_md.s，大容量选hd.s）；
      • Library文件夹：
        • 复制Libraries\CMSIS\CM3\DeviceSupport\ST\STM32F10x下的stm32f10x.h、system_stm32f10x.h、system_stm32f10x.c；
        • 复制Libraries\STM32F10x_StdPeriph_Driver\src（所有.c）和inc（所有.h）下的文件；
      • User文件夹：复制固件库根目录的stm32f10x_conf.h、stm32f10x_it.h、stm32f10x_it.c，并新建空白main.c。
  • 核心作用：按功能分类管理文件，避免源码混乱；本地化固件库文件，防止工程依赖外部路径。
  • 新手避坑：启动文件需匹配芯片容量（C8T6=中容量=md，ZET6=大容量=hd），漏选/错选会导致undefined symbol __main编译错误。
  • 3. 工程里对应建立Start、Library、User等同名称的分组，然后将文件夹内的文件添加到工程分组里
  • 操作细节：
    1. 在Keil左侧Project窗口，右键Target 1 → Manage Project Items。
    2. 在Groups栏点击Add，依次创建Start、Library、User分组，点击OK。
    3. 右键对应分组 → Add Existing Files to Group：
      • Start分组：添加Start文件夹下的startup_stm32f10x_md.s；
      • Library分组：添加Library文件夹下所有.c文件（如stm32f10x_gpio.c、stm32f10x_rcc.c）；
      • User分组：添加User文件夹下的main.c、stm32f10x_it.c、system_stm32f10x.c。
  • 核心作用：将本地文件与Keil工程关联，让编译器识别并编译这些源码。
  • 新手避坑：不要漏加启动文件（.s），否则链接阶段会提示“找不到程序入口”。
  • 4. 工程选项，C/C++，Include Paths内声明所有包含头文件的文件夹
  • 操作细节：
    1. 点击Keil工具栏魔法棒图标 → 切换到C/C++选项卡。
    2. 点击Include Paths右侧的...按钮，在弹窗中点击Add，依次添加3个文件夹路径：
      • .\Start（当前工程目录下的Start文件夹）；
      • .\Library；
      • .\User。
    3. 点击OK保存配置。
  • 核心作用：告诉编译器头文件的存放位置，避免xxx.h: No such file or directory编译错误。
  • 新手避坑：路径用相对路径（.\表示当前工程目录），而非绝对路径（如D:\STM32\Project），便于工程移植。
  • 5. 工程选项，C/C++，Define内定义USE_STDPERIPH_DRIVER
  • 操作细节：
    1. 在C/C++选项卡的Define输入框中，输入USE_STDPERIPH_DRIVER（大小写严格匹配，无引号）。
    2. （可选）补充定义HSE_VALUE=8000000（匹配8MHz外部晶振，与开发板硬件一致）。
  • 核心作用：启用STM32标准库驱动（标准库通过该宏控制头文件/include逻辑，未定义则无法使用GPIO_Init等库函数）。
  • 新手避坑：宏名拼写错误（如少写_DRIVER）会导致标准库函数编译失败。
  • **6. 工程选项，Debug，下拉列表选择对应调试器，Settings，Flash Download里勾选Reset and Run
  • 操作细节：
    1. 切换到Debug选项卡，在Use下拉列表选择实际使用的调试器（如ST-Link Debugger），点击Settings。
    2. 在Debug页面：
      • Port选择SW（SWD模式，仅需4根线，比JTAG省引脚）；
      • Clock设为4MHz（降低时钟避免通信不稳定）；
      • 勾选Reset after Connect。
    3. 切换到Flash Download选项卡：
      • 勾选Erase Full Chip（全片擦除，清除旧程序）；
      • 勾选Program（烧录程序到Flash）；
      • 勾选Verify（校验烧录结果）；
      • 勾选Reset and Run（烧录完成后自动复位并运行程序）。
    4. 确认Programming Algorithm中添加了对应芯片的Flash算法（如STM32F10x Medium-density Flash），点击OK保存。
  • 核心作用：配置调试器和烧录参数，确保程序能正确下载到STM32并自动运行。
  • 新手避坑：
    • 调试器型号需与实物一致（ST-Link不要选J-Link）；
    • Flash算法需匹配芯片容量（中容量选Medium-density），否则会提示Flash Download failed。
