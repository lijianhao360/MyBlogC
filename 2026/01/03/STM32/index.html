Day-01 初识 STM32 与工程搭建

1. STM32 概述

  • 什么是 STM32？

    • STM32 是 ST（意法半导体）公司基于 ARM Cortex‑M 内核开发的 32 位微控制器（MCU）。
    • 具备功能强大、性能优异、片上资源丰富、功耗低等特点，是一款经典的嵌入式微控制器。
    • 应用场景：广泛应用于智能车、无人机、机器人、无线通信、物联网、工业控制、消费电子等领域。

  • 关于 ARM：

    • ARM 既指 ARM 公司，也指 ARM 处理器架构（内核）。
    • ARM 公司是全球领先的半导体 IP 提供商，全世界超过 95% 的智能设备都采用 ARM 架构。
    • 生态分工：ARM 公司负责设计内核，ST 等半导体厂商在内核基础上完善周边外设电路，并生产出最终的芯片。

💡 核心原理解析：0x00000010 是怎么来的？

理解十六进制与二进制的转换以及寄存器位编号

1. 十六进制转二进制（找有效位）
0x00000010 是 32 位寄存器的完整写法，核心有效位是最后的 10。

  • 0x10（十六进制） = 16（十进制） = 2⁴
  • 二进制中“2的 n 次方”代表第 n 位为 1，其余全为 0。因此 0x10 对应的二进制就是第 4 位为 1（即 0001 0000）。

2. 对应寄存器位（从 0 开始数）
寄存器位编号遵循“从右往左，从 0 开始数”。以 APB2ENR 寄存器低 8 位为例：

位编号 7 6 5 4 (IOPCEN) 3 (IOPBEN) 2 (IOPAEN) 1 0
二进制 0 0 0 1 0 0 0 0
十六进制 0x80 0x40 0x20 0x10 0x08 0x04 0x02 0x01

⚠️ 新手避坑指南：
很多新手会误以为 0x10 对应第 10 位或第 16 位。记住公式：2ⁿ 对应第 n 位。0x10 = 2⁴，所以正好对应开启 GPIOC 时钟的第 4 位！

3. GPIO 初始化（标准库函数版）

直接操作寄存器虽然高效，但可读性差且容易出错。实际开发中，我们更多使用STM32标准库来完成相同的功能。

4. Keil 新建工程标准步骤

为了规范代码管理，新建一个标准的 STM32 工程需要以下 6 步：

  1. 建立物理文件夹：在非系统盘新建总工程文件夹（禁用中文路径），并在内部创建 Start、Library、User 三个子文件夹。
  2. 复制固件库文件：
    • Start：放入启动文件（如 startup_stm32f10x_md.s）。
    • Library：放入标准库的 .c 和 .h 源码文件。
    • User：放入 stm32f10x_conf.h、中断文件及自行创建的 main.c。
  3. Keil 工程内部分组：在 Keil 中创建同名的 Start、Library、User Group，并将上述文件一一添加进去。
  4. 配置头文件路径：魔术棒工具 -> C/C++ -> Include Paths，将三个文件夹的相对路径（如 .\User）添加进去。
  5. 定义全局宏：魔术棒工具 -> C/C++ -> Define，填入 USE_STDPERIPH_DRIVER（启用标准库）。
  6. 配置调试与烧录：
    • Debug：选择对应的调试器（如 ST-Link），端口选 SW，勾选 Reset after Connect。
    • Flash Download：勾选 Reset and Run 并确认添加了正确的 Flash 算法。

Day-02 GPIO 深入解析

1. GPIO 简介

GPIO (General Purpose Input Output) 即通用输入输出端口，是单片机与外部硬件交互的核心接口。

  • 电平特性：标准工作电平为 0V~3.3V，部分引脚具备容忍 5V 的能力。
  • 核心功能分类：
分类 具体模式 典型应用场景
输出模式 推挽、开漏、复用推挽、复用开漏 驱动 LED、蜂鸣器、继电器、I2C/SPI 时序输出
输入模式 浮空、上拉、下拉、模拟输入 按键检测、红外接收、传感器信号读取、ADC 采集

2. GPIO 基本架构与数据流向

GPIO 的运行逻辑可以划分为三个核心层级：

  1. 上层（通信枢纽）- APB2 总线：连接 CPU 与外设，负责时钟使能和数据传输。
  2. 中层（软件接口）- 寄存器组：存储配置参数（模式/速度）和电平状态，代码操作的本质就是读写这些寄存器。
  3. 下层（硬件执行）- 驱动器与引脚：将数字信号转换为实际的高低电平，或对外部输入信号进行采样滤波。

数据流向逻辑：

  • 输出：CPU -> 写入输出数据寄存器 -> 驱动器 -> 引脚输出电平。
  • 输入：外部信号 -> 引脚 -> 驱动器采样 -> 输入数据寄存器 -> CPU 读取。

3. GPIO 位结构详解

理解引脚内部的硬件电路，是弄懂 8 种工作模式的终极钥匙。单个引脚内部主要包含以下核心模块：

① 输入驱动电路（输入模式核心）

  • TTL 肖特基触发器：负责将不稳定的模拟电平“整形”为标准的数字电平（高/低），有效抑制噪声。
  • 上拉/下拉电阻：
    • 上拉输入：引脚悬空时默认高电平，适合接低电平触发的按键。
    • 下拉输入：引脚悬空时默认低电平。

② 输出驱动电路（输出模式核心）

  • P-MOS / N-MOS 架构：
    • 推挽输出 (Push-Pull)：P-MOS 和 N-MOS 交替导通。可主动输出强高/低电平，驱动能力强，适合直接点亮 LED。
    • 开漏输出 (Open-Drain)：只有 N-MOS 工作。只能主动输出低电平，高电平需要依靠外部上拉电阻实现。多用于 I2C 等总线通信，防止多设备总线冲突。
    • 关闭状态：两者均关闭，引脚呈高阻态（用于输入模式）。
  • 复用功能切换：可将输出控制权从普通寄存器转移给片上外设（如 UART、SPI）。

③ 保护电路

  • 引脚内部设有上下两个保护二极管。当输入电压高于 3.3V 或低于 0V 时，二极管导通，防止异常电压直接击穿内部核心电路，实现 ESD 静电防护。

4.1 LED闪烁

  • 核心注释补充说明（新手重点）

  1. 位运算核心逻辑：
    代码中~0x0001这类写法是嵌入式编程的常用技巧——利用「按位取反」快速得到「仅单个引脚低电平、其余全高电平」的数值，比手动写0xFFFE更直观，也避免了计算错误。

  2. 流水灯节奏设计：
    前4个引脚（PA0PA3）用100ms延时实现「快速流水」，后4个引脚（PA4PA7）用500ms延时实现「慢速流水」，形成视觉上的快慢对比，是嵌入式小项目的常见创意。

  3. 新手易踩坑点：

    • 忘记开启GPIO时钟：会导致引脚配置无效，LED完全不亮；
    • 头文件拼写错误（如DElay.h）：编译时会提示No such file or directory；
    • GPIO_Write参数写反：若写成0x0001而非~0x0001，会变成「PA0灭、其余亮」，和预期效果相反。
  • 总结
  1. 代码核心逻辑：开GPIOA时钟 → 配置PA0~PA7为推挽输出 → 死循环中用GPIO_Write+按位取反控制单个引脚亮灭，配合不同延时实现快慢流水灯；
  2. 关键知识点：GPIO_Write的批量电平控制、按位取反~的用法、STM32外设时钟的必开规则；
  3. 设计巧思：快慢延时的搭配让流水灯有节奏差异，比单一速度更有层次感。

枚举（enum）是C语言中用户自定义的常量类型，核心作用是给一组整数常量起“有意义的名字”，替代直接写数字（魔法数字），让代码更易读、易维护。下面用2个贴合实际开发的例子，从基础到进阶帮你理解：

  • **示例1：基础枚举（表示星期）**4
    这是枚举最经典的用法，用名字替代0~6的数字表示星期：
  • 示例2：进阶枚举（自定义初始值+实际业务场景）
    实际开发中常自定义枚举常量的初始值（比如表示设备状态），让枚举值更贴合业务：
  • 枚举的核心优势（为什么不用直接写数字）
  1. 可读性提升：ONLINE比数字1更直观，一眼能看懂含义；
  2. 可维护性提升：若需修改状态值（比如把ERROR从5改成10），只需改枚举定义，无需改所有用到5的地方；
  3. 类型安全：枚举变量只能赋值枚举常量，减少传错值的风险（比如不会把100这种无效值赋给设备状态）；
  4. 代码简洁：避免重复定义宏常量（如#define OFFLINE 0）。
  • 总结
  1. 枚举本质是有名字的整数常量，默认从0开始递增，也可手动指定初始值；
  2. 枚举适合定义“一组互斥的常量”（如星期、状态、颜色、指令码）；
  3. 核心价值：用“语义化名字”替代魔法数字，让代码更易读、易维护。

  • 核心知识点补充

    • GPIO_SetBits(置高) → LED灭；

  3. 设计思路：按“功能拆分”封装函数（初始化/亮/灭/翻转），符合嵌入式模块化编程规范，便于main函数调用。

核心知识点补充（嵌入式按键开发）

1. 上拉输入（GPIO_Mode_IPU）的硬件逻辑

状态 引脚电平 GPIO_ReadInputDataBit返回值
按键未按下 高电平 1
按键按下 低电平 0
  • 硬件接线：按键一端接GPIOB1/B11，另一端接GND（地），配合内部上拉电阻实现电平变化。

2. 软件消抖的原理

按键是机械结构，按下/松开时会有10~20ms的“电平抖动”（快速高低跳变），直接检测会误判多次按下。
代码中两次Delay_ms(20)的作用：

  • 第一次：按下后延时20ms，跳过抖动期，确认是真实按下；
  • 第二次：释放后延时20ms，跳过松手抖动，避免误触发。

3. 函数设计逻辑

  • KEY_Init()：初始化按键引脚为上拉输入，仅需在程序开头调用一次；
  • Key_GetNum()：每次调用都会检测按键状态，返回按键编号，适合在main函数的死循环中轮询调用。

总结

  1. 代码核心功能：初始化GPIOB1/B11为上拉输入，检测按键按下（带消抖）并返回按键编号；
  2. 关键错误：按键2的释放等待引脚写错（B1→B11），修正后才能正常检测按键2；
  3. 设计思路：符合嵌入式按键开发的“初始化+轮询读取+消抖”标准流程，是按键控制的基础模板。

    EXTI 外部中断控制器，检测电平变化，触发中断
    NVIC 中断优先级控制器，管理中断执行顺序

  • 4. 中断触发逻辑

  1. 传感器输出高电平 → 低电平（下降沿）；
  2. EXTI检测到电平变化，触发中断；
  3. CPU暂停主程序，执行 EXTI15_10_IRQHandler；
  4. 计数+1 → 清除中断标志 → 回到主程序。

Day-05 TIM定时中断

1. TIM简介

TIM（Timer）定时器
-核心定义
定时器是对输入时钟进行计数的外设，并在计数值达到设定值时触发中断。

  • 基础结构与特性

  1. 时基单元

    • 包含：16位计数器、预分频器、自动重装寄存器
    • 核心能力：在 72MHz 计数时钟 下，最大可实现 59.65秒 的定时（由16位寄存器最大值决定：$2^{16}-1 = 65535$，计算时间约为 $65535/72MHz \approx 59.65s$）

  2. 功能拓展

    • 基础功能：定时中断
    • 高级功能：内外时钟源选择、输入捕获、输出比较、编码器接口、主从触发模式等

  3. 分类（按复杂度与应用场景）

    • 高级定时器
    • 通用定时器
    • 基本定时器

3.1 定时器中断

  • 核心知识点补充（必看）

  1. 定时时间计算
    内部时钟 = 72MHz
    分频后时钟 = 72MHz / (7200) = 10kHz
    中断周期 = 10000 / 10kHz = 1秒
    最终效果：定时器每1秒触发一次中断

  2. 关键配置说明

    • TIM_Period：自动重装值，决定计数器溢出上限
    • TIM_Prescaler：预分频器，降低计数器计数速度
    • NVIC优先级：配置中断的执行优先级，防止多中断冲突
    • 中断标志位：必须手动清除，否则程序会卡死在中断中

  3. 代码逻辑
    初始化流程：开时钟 → 配时钟源 → 设时基参数 → 开中断 → 配NVIC → 启动定时器
