Day-01 初识 STM32 与工程搭建

1. STM32 概述

  • 什么是 STM32？

    • STM32 是 ST（意法半导体）公司基于 ARM Cortex‑M 内核开发的 32 位微控制器（MCU）。
    • 具备功能强大、性能优异、片上资源丰富、功耗低等特点，是一款经典的嵌入式微控制器。
    • 应用场景：广泛应用于智能车、无人机、机器人、无线通信、物联网、工业控制、消费电子等领域。

  • 关于 ARM：

    • ARM 既指 ARM 公司，也指 ARM 处理器架构（内核）。
    • ARM 公司是全球领先的半导体 IP 提供商，全世界超过 95% 的智能设备都采用 ARM 架构。
    • 生态分工：ARM 公司负责设计内核，ST 等半导体厂商在内核基础上完善周边外设电路，并生产出最终的芯片。

我帮你逐个拆解这5个关键引脚的功能、电路设计要点和实际用法，结合你图里的标注来讲：

    1. VDD（供电+，接3.3V）
  • 核心功能：STM32的数字电源输入引脚，为MCU的数字电路（CPU、外设、GPIO）供电，图中标注的VDD_1/VDD_2/VDD_3是多个电源域，都需要接3.3V（标准电压范围2.0~3.6V）。
  • 电路设计要点：
    • 每个VDD引脚都必须接3.3V，且旁边要加一个0.1μF的去耦电容到地，滤除电源噪声，保证供电稳定。
    • 图中还有VDDA（模拟电源），是给ADC、RTC等模拟模块供电的，也要接3.3V，通常和数字VDD共用电源，可额外加RC滤波（如10Ω电阻+1μF电容）减少噪声干扰。
    1. VSS（地，接0V）
  • 核心功能：STM32的电源地（GND）引脚，为MCU提供0V参考电位，图中标注的VSS_1/VSS_2/VSS_3/VSSA是数字地和模拟地，都需要可靠接系统地。
  • 电路设计要点：
    • 所有VSS引脚都必须接地，保证电源回路完整，否则MCU无法正常工作。
    • VSSA是模拟地，和数字地建议单点连接（比如在电源入口处共地），避免数字电路的噪声串扰到模拟电路，影响ADC等外设的精度。
    1. NRST（复位，接复位按钮）
  • 核心功能：低电平复位引脚，当输入低电平时，MCU会强制复位（回到初始状态，程序从复位地址重新执行）；高电平时，MCU正常运行。
  • 电路设计要点：
    • 必须外接一个10kΩ上拉电阻到VDD，默认保持高电平。
    • 同时接一个复位按钮到地，按下按钮时NRST拉低，实现手动复位；可额外并联一个0.1μF电容到地，防止电源波动导致的误复位。
    1. VBAT（备用电池）
  • 核心功能：备份域电源引脚，给MCU的RTC实时时钟和备份寄存器供电。当主电源VDD掉电时，VBAT供电，保持RTC继续运行、备份寄存器的数据不丢失。
  • 电路设计要点：
    • 图中左侧的纽扣电池（SR626EH）就是接在这里的，通常使用3V纽扣电池（如CR2032、SR626）。
    • 当主电源VDD正常供电时，VBAT会由内部电源自动供电，电池不工作；只有VDD掉电时，才会切换到电池供电。
    • 如果项目不需要RTC功能，可直接将VBAT接VDD（3.3V），不接电池。
    1. BOOT0（启动模式选择）
  • 核心功能：和BOOT1配合，决定MCU的启动模式（程序从哪里加载），是STM32的关键配置引脚。
  • 三种常用启动模式：
    BOOT0状态 BOOT1状态 启动模式 用途
    低电平（0） 任意 主闪存启动 正常模式，从用户烧录的Flash程序启动，是项目默认模式
    高电平（1） 低电平（0） 系统存储器启动 从内置BootLoader启动，用于串口（ISP）下载程序
    高电平（1） 高电平（1） 内置SRAM启动 调试用，从SRAM加载程序，几乎不用
  • 电路设计要点：
    • 常规用法：接一个10kΩ下拉电阻到地，默认保持低电平，让MCU从Flash启动。
    • 预留调试接口：可额外接一个排针/开关，方便将BOOT0拉高，进入串口下载模式（比如用串口给MCU烧录程序时，需要临时拉高BOOT0）。
  • 补充：这几个引脚的优先级
  • VDD/VSS是基础：电源和地接不好，MCU根本无法启动。
  • NRST是复位保障：电路异常时，复位是恢复MCU的关键。
  • BOOT0决定启动方式：接错会导致MCU无法正常运行程序。
  • VBAT是RTC备份：不接也不影响主程序运行，但掉电后RTC会停止计时。

2. GPIO 初始化（寄存器初体验）

以下这段代码是基于 STM32F10x 系列最基础的寄存器操作，核心目标是：配置 GPIOC 的第 13 引脚为推挽输出模式，并将该引脚置为低电平。

💡 核心原理解析：0x00000010 是怎么来的？

理解十六进制与二进制的转换以及寄存器位编号

1. 十六进制转二进制（找有效位）
0x00000010 是 32 位寄存器的完整写法，核心有效位是最后的 10。

  • 0x10（十六进制） = 16（十进制） = 2⁴
  • 二进制中“2的 n 次方”代表第 n 位为 1，其余全为 0。因此 0x10 对应的二进制就是第 4 位为 1（即 0001 0000）。

2. 对应寄存器位（从 0 开始数）
寄存器位编号遵循“从右往左，从 0 开始数”。以 APB2ENR 寄存器低 8 位为例：

位编号 7 6 5 4 (IOPCEN) 3 (IOPBEN) 2 (IOPAEN) 1 0
二进制 0 0 0 1 0 0 0 0
十六进制 0x80 0x40 0x20 0x10 0x08 0x04 0x02 0x01

⚠️ 新手避坑指南：
很多新手会误以为 0x10 对应第 10 位或第 16 位。记住公式：2ⁿ 对应第 n 位。0x10 = 2⁴，所以正好对应开启 GPIOC 时钟的第 4 位！

3. GPIO 初始化（标准库函数版）

  • 一、4个GPIO核心函数（底层原理+用法+你的实战场景）

  1. GPIO_Init
    GPIO的初始化配置函数，是所有引脚操作的基础，必须第一个调用。
    作用：指定引脚号、设置引脚工作模式、配置引脚速度。
    你的代码场景：电机驱动初始化PA4/PA5、PWM初始化PA2、按键初始化引脚，全靠这个函数配置模式。

  2. GPIO_WriteBit
    引脚输出控制函数，底层操作输出数据寄存器(ODR)。
    作用：给单个引脚写入高电平或低电平，直接控制硬件电平。
    你的代码场景：控制电机正反转时，用它设置PA4/PA5的高低电平。

  3. GPIO_ReadInputDataBit
    引脚输入读取函数，底层操作输入数据寄存器(IDR)。
    作用：读取引脚外部真实的电平状态，不受程序配置影响，是输入功能的核心。
    你的代码场景：按键检测时，用它读取引脚电平，判断按键是否按下。

  4. GPIO_ReadOutputDataBit
    输出状态读取函数，底层读取输出数据寄存器(ODR)。
    作用：读取程序设置的输出电平(就是你刚刚给引脚设置的电平)，不是引脚实际电平，仅用于调试，日常几乎不用。

  • 二、GPIO输出模式&硬件结构（核心区别+你的代码匹配）

  1. 引脚信号来源
    普通输出：由CPU程序直接控制引脚电平（比如电机方向引脚）；
    复用输出：引脚被片内外设接管（定时器PWM、串口），CPU无法直接控制，完全由外设驱动。

  2. 推挽输出（GPIO_Mode_Out_PP）
    最常用的输出模式，内部两个MOS管都工作；
    高电平直接输出3.3V，低电平直接输出0V，驱动能力极强；
    你的代码场景：电机方向控制引脚PA4、PA5，全部用这个模式。

  3. 复用推挽输出（GPIO_Mode_AF_PP）
    外设专用输出模式，引脚交给定时器、串口等外设控制；
    保留推挽输出的强驱动能力，是PWM波形输出的固定必备模式；
    你的代码场景：PWM输出引脚PA2，必须配置这个模式。

  4. 开漏输出（了解即可）
    仅能输出低电平，高电平需要外接上拉电阻，无驱动能力；
    专用场景：I2C通信，你的电机、PWM代码中完全用不到。

  • 三、极简实战总结（贴合你的项目）
  1. 控制电机、LED这类普通硬件 → 用推挽输出 + GPIO_WriteBit；
  2. 输出PWM波形 → 用复用推挽输出，引脚由定时器自动控制；
  3. 读取按键、传感器 → 用GPIO_ReadInputDataBit读真实电平；
  4. 所有引脚，必须先调用GPIO_Init初始化，才能正常工作。

直接操作寄存器虽然高效，但可读性差且容易出错。实际开发中，我们更多使用STM32标准库来完成相同的功能。

4. Keil 新建工程标准步骤

为了规范代码管理，新建一个标准的 STM32 工程需要以下 6 步：

  1. 建立物理文件夹：在非系统盘新建总工程文件夹（禁用中文路径），并在内部创建 Start、Library、User 三个子文件夹。
  2. 复制固件库文件：
    • Start：放入启动文件（如 startup_stm32f10x_md.s）。
    • Library：放入标准库的 .c 和 .h 源码文件。
    • User：放入 stm32f10x_conf.h、中断文件及自行创建的 main.c。
  3. Keil 工程内部分组：在 Keil 中创建同名的 Start、Library、User Group，并将上述文件一一添加进去。
  4. 配置头文件路径：魔术棒工具 -> C/C++ -> Include Paths，将三个文件夹的相对路径（如 .\User）添加进去。
  5. 定义全局宏：魔术棒工具 -> C/C++ -> Define，填入 USE_STDPERIPH_DRIVER（启用标准库）。
  6. 配置调试与烧录：
    • Debug：选择对应的调试器（如 ST-Link），端口选 SW，勾选 Reset after Connect。
    • Flash Download：勾选 Reset and Run 并确认添加了正确的 Flash 算法。

Day-02 GPIO 深入解析

1. GPIO 简介

GPIO (General Purpose Input Output) 即通用输入输出端口，是单片机与外部硬件交互的核心接口。

  • 电平特性：标准工作电平为 0V~3.3V，部分引脚具备容忍 5V 的能力。

  • GPIO的8种工作模式：

    分类 具体模式 典型应用场景
    4种输出模式 通用输出推挽、通用输出开漏、复用输出推挽、复用输出开漏 驱动 LED、蜂鸣器、继电器、I2C/SPI 时序输出
    4种输入模式 输入浮空、输入上拉、输入下拉、模拟输入 按键检测、红外接收、传感器信号读取、ADC 采集

  • 推挽和开漏

2. GPIO 基本架构与数据流向

GPIO 的运行逻辑可以划分为三个核心层级：

  1. 上层（通信枢纽）- APB2 总线：连接 CPU 与外设，负责时钟使能和数据传输。
  2. 中层（软件接口）- 寄存器组：存储配置参数（模式/速度）和电平状态，代码操作的本质就是读写这些寄存器。
  3. 下层（硬件执行）- 驱动器与引脚：将数字信号转换为实际的高低电平，或对外部输入信号进行采样滤波。

数据流向逻辑：

  • 输出：CPU -> 写入输出数据寄存器 -> 驱动器 -> 引脚输出电平。
  • 输入：外部信号 -> 引脚 -> 驱动器采样 -> 输入数据寄存器 -> CPU 读取。

3. GPIO 位结构详解

理解引脚内部的硬件电路，是弄懂 8 种工作模式的终极钥匙。单个引脚内部主要包含以下核心模块：

① 输入驱动电路（输入模式核心）


  • TTL 肖特基触发器：负责将不稳定的模拟电平“整形”为标准的数字电平（高/低），有效抑制噪声。

  • 上拉/下拉电阻：

    • 上拉输入：引脚悬空时默认高电平，适合接低电平触发的按键。(引脚悬空就是引脚没有接电流)
    • 下拉输入：引脚悬空时默认低电平。

② 输出驱动电路（输出模式核心）

  • P-MOS / N-MOS 架构：
  • 推挽输出 (Push-Pull)：P-MOS 和 N-MOS 交替导通。可主动输出强高/低电平，驱动能力强，适合直接点亮 LED。
  • 开漏输出 (Open-Drain)：只有 N-MOS 工作。只能主动输出低电平，高电平需要依靠外部上拉电阻实现。多用于 I2C 等总线通信，防止多设备总线冲突。
  • 关闭状态：两者均关闭，引脚呈高阻态（用于输入模式）。
  • 复用功能切换：可将输出控制权从普通寄存器转移给片上外设（如 UART、SPI）。

③ 保护电路

  • 引脚内部设有上下两个保护二极管。当输入电压高于 3.3V 或低于 0V 时，二极管导通，防止异常电压直接击穿内部核心电路，实现 ESD 静电防护。

1. 串口通信协议

我帮你把串口通信的核心逻辑，结合你的描述和图里的连接方式，总结成清晰的几点：

  • 一、硬件连接核心（图里的交叉线）
    串口通信必须用交叉连接：
  • 发送方的Tx（发送引脚）接接收方的Rx（接收引脚）
  • 接收方的Tx接发送方的Rx
    这样才能让一方的输出，正确传到另一方的输入，实现数据收发。
  • 二、帧传输的核心逻辑
    你说的是异步串口（UART）的标准帧传输规则，核心是用电平变化来区分“空闲/开始/数据/结束”：

  1. 空闲状态：线路保持高电平（逻辑1）
    没有数据传输时，发送方的Tx引脚一直是高电平，接收方看到持续高电平，就知道线路处于空闲状态，没有数据在传。

  2. 起始位：拉低电平（发逻辑0），标志传输开始
    要发数据时，发送方先把Tx拉低，发一个低电平的“起始位”。
    这个下降沿是给接收方的同步信号：“我要开始发数据了，你准备好采样！”，解决了异步串口没有时钟线的同步问题。

  3. 数据传输：按位发0/1，对应低/高电平
    起始位之后，发送方按约定的波特率，逐位发数据：逻辑0用低电平表示，逻辑1用高电平表示。

  4. 停止位：拉高电平（发逻辑1），标志传输结束
    数据发完后，发送方把Tx拉高，发一个高电平的“停止位”，告诉接收方：“这一帧数据发完了，线路回到空闲状态，你可以准备接收下一帧了。”

  • 一句话总结
    串口通信靠“交叉线”实现收发对接，用“空闲高电平+起始位拉低+数据位+停止位拉高”的规则，在没有时钟线的情况下，让收发双方同步并完成数据帧的传输。

Day-06 SPI总线

1.SPI总线基本概念

  • 1.SPI总线的电路结构

  • 核心知识点：
    SPI总线是一种同步串行通信总线，采用主从架构，核心由4根信号线组成（部分场景可省略）：
    ①SCLK（串行时钟）：由主设备产生，控制通信时序；
    ②MOSI（主出从入）：主设备向从设备发送数据的通道；
    ③MISO（主入从出）：从设备向主设备反馈数据的通道；
    ④SS（从设备选择）：主设备通过拉低对应从设备的SS引脚，选中该从设备进行通信（未选中的从设备处于高阻态，不参与通信）。SPI总线支持多从设备挂载，同一时刻仅能有一个从设备被选中。

  • 2.通信流程和波形

  • 核心知识点：
    SPI通信为同步通信，全程由SCLK时钟同步，完整流程分为3步：
    ①初始化：主设备配置SCLK频率、时钟极性/相位、数据传输顺序等参数，拉低目标从设备的SS引脚，选中该设备；
    ②数据传输：主设备通过MOSI发送数据，同时通过MISO接收从设备数据，每一个SCLK时钟周期传输1位数据，发送和接收同步进行；
    ③通信结束：主设备拉高SS引脚，释放从设备，停止SCLK时钟，完成一次通信。波形图中需重点关注SCLK、MOSI、MISO、SS四根信号的时序对应关系，SS引脚拉低后通信开始，拉高后通信终止。
  • 3.参数1:时钟信号的极性和相位
  • 核心知识点：

  • 时钟极性（CPOL）定义SCLK空闲状态的电平：
    CPOL=0时，SCLK空闲时为低电平；CPOL=1时，SCLK空闲时为高电平。极性决定了时钟信号的“基准电平”，是区分时钟模式的关键参数之一，直接影响数据采样的基准状态。

  • 时钟相位（CPHA）定义数据采样的边沿：
    CPHA=0时，在SCLK的第一边沿（空闲电平到工作电平的跳变）采样数据；CPHA=1时，在SCLK的第二边沿（工作电平回到空闲电平的跳变）采样数据。
    结合前面的说明：下降沿叫第一边沿，上升沿叫第二边沿，需注意边沿方向与CPOL的联动（不同CPOL下，第一/第二边沿的电平跳变方向不同）。
    补充：极性和相位共同决定SPI的时钟模式，二者组合可形成4种不同的通信时序。

  • 下降沿叫第一边沿，上升沿叫第二边沿

  • 4.四种时钟模式

  • 核心知识点：
    四种时钟模式由CPOL（极性）和CPHA（相位）的组合决定，是SPI通信的核心配置，四种模式详情如下：①模式0（CPOL=0，CPHA=0）：SCLK空闲低电平，第一边沿（上升沿）采样，第二边沿（下降沿）输出，是最常用的模式；②模式1（CPOL=0，CPHA=1）：SCLK空闲低电平，第一边沿（上升沿）输出，第二边沿（下降沿）采样；③模式2（CPOL=1，CPHA=0）：SCLK空闲高电平，第一边沿（下降沿）采样，第二边沿（上升沿）输出；④模式3（CPOL=1，CPHA=1）：SCLK空闲高电平，第一边沿（下降沿）输出，第二边沿（上升沿）采样。实际应用中，主从设备必须配置相同的时钟模式，否则会出现数据传输错误。

  • 5.参数2:比特位的传输顺序

  • 核心知识点：
    SPI总线支持两种比特位传输顺序，由设备寄存器配置决定：
    ①MSB先行（最常用）：数据的最高位（Most Significant Bit）先传输，符合大多数SPI设备的默认配置；
    ②LSB先行：数据的最低位（Least Significant Bit）先传输，仅用于部分特殊设备（需主从设备一致配置）。传输顺序错误会导致接收端解析的数据完全错误，是SPI通信调试的常见易错点。

  • 6.参数3:数据宽度

  • 核心知识点：
    数据宽度指一次SPI通信中传输的数据位数，由主从设备共同约定，最常用的是8位（1字节），部分设备支持16位、32位等宽数据传输（如STM32的SPI外设可配置8/16位数据宽度）。数据宽度决定了一次通信可传输的数据量，配置时需确保主从设备的数据宽度一致，否则会出现数据截断或错位。

  • 一、整体概览：SPI的核心定位

  • 二、分模块详解（对应结构图）

    1. 核心收发通路：SPI的“数据双向通道”
      这是SPI通信的核心，对应图中上方的发送数据寄存器、移位寄存器、接收数据寄存器，以及MOSI/MISO两个引脚。

  • （1）发送通路（主机→从机）

  • 流程：你写的数据先存入「发送数据寄存器」，硬件自动把数据加载到发送移位寄存器，然后在SCK时钟驱动下，一位一位从MOSI引脚串行发送出去。

  • 关键标志位：TxE（发送寄存器空），图中标注为0/1，当发送数据寄存器为空时，TxE=1，表示你可以写下一个数据了。

  • 对应你的代码：PB5引脚配置为GPIO_Mode_AF_PP（复用推挽输出），就是因为它作为主机的MOSI引脚，由SPI外设直接控制输出数据，推挽模式驱动能力更强。

  • （2）接收通路（从机→主机）

  • 流程：从机发送的数据，在SCK时钟驱动下，一位一位从MISO引脚进入接收移位寄存器，完整接收8位后，数据自动存入「接收数据寄存器」，供CPU读取。

  • 关键标志位：RxNE（接收数据寄存器非空），当有数据接收完成时，RxNE=1，表示你可以读取数据了；ORV（溢出错误），如果数据没及时读取，下一次接收就会触发溢出错误。

  • 对应你的代码：PB4引脚配置为GPIO_Mode_IPU（上拉输入），因为它作为主机的MISO引脚，是输入模式，上拉电阻可以防止空闲时电平浮动，避免误接收数据。

  • （3）SPI的核心特点：同步全双工
    你可以注意到，图中的发送和接收移位寄存器是联动的——主机每发1位数据，就会同时从从机接收1位数据，收发是同步进行的。

  • 这意味着：SPI通信没有“只发送不接收”或“只接收不发送”的情况，发送的同时一定在接收，接收的同时也在发送。

  • 新手常见坑：只写发送函数，不读取接收寄存器，会导致接收数据一直堆积，触发ORV溢出错误。

    1. 时钟控制模块：SPI通信的“同步节拍器”
      对应图中下方的时钟控制单元，是SPI通信的“心脏”，决定了通信的速率和时序。

  • （1）时钟生成

  • 时钟来源：来自APB总线时钟（比如STM32F1的APB1/APB2时钟），经过预分频器（÷2/4/.../256）分频后，生成SCK时钟信号，从SCK引脚输出。

  • 对应你的代码：PB3引脚配置为GPIO_Mode_AF_PP，因为它作为主机的SCK引脚，由SPI外设输出时钟信号，推挽模式保证时钟波形干净。

  • 波特率配置：你后续写SPI初始化时，需要配置预分频值，比如预分频16，就能得到400KHz的通信速率。

  • （2）时钟极性（CPOL）和相位（CPHA）
    这是SPI通信的关键配置，决定了数据采样的时序，对应图中的“极性”和“相位”输入：

  • CPOL（时钟极性）：空闲时SCK的电平，0表示空闲低电平，1表示空闲高电平。

  • CPHA（时钟相位）：数据采样的边沿，0表示第一个边沿采样，1表示第二个边沿采样。

  • 这两个配置组合出SPI的4种工作模式（模式0~3），必须和从机设备的配置一致，否则无法通信。

    1. NSS片选控制：SPI的“设备开关”
      对应图中右侧的NSS引脚，用于选中/取消选中从机设备，分为两种模式：

  • （1）硬件NSS模式
    由SPI外设自动控制NSS引脚，主机模式下，硬件自动拉低NSS选中从机，通信结束后自动拉高，无需软件干预。

  • （2）软件NSS模式

  • 拉低PA15，选中从机；拉高PA15，释放从机。

  • 这种方式更灵活，适合多设备挂载在同一个SPI总线上的场景。

    1. 通信方向选择：主/从模式与数据格式
      对应图中下方的“通信方向选择”模块，决定了SPI的工作模式：

  • （1）主/从模式

  • 主机模式：由主机生成SCK时钟信号，控制通信时序，从机只能被动响应，无法主动发起通信。你写的代码就是主机模式，所以SCK/MOSI都是输出模式。

  • 从机模式：由外部主机提供SCK时钟，从机根据时钟信号收发数据，适合传感器、OLED这类外设。

  • （2）数据传输模式

  • 2线全双工：同时使用MOSI和MISO，收发同时进行，是最常用的模式，你的代码就是这种配置。

  • 2线只读：主机只接收数据，不发送数据。

  • 单线发送/接收：只用一根线半双工通信，不常用。

  • 2.SPI_Init 初始化

SPI_Init 是STM32硬件SPI外设的核心初始化函数，必须基于GPIO引脚初始化、SPI时钟使能后配置。通过SPI_InitTypeDef结构体对SPI的全部工作参数进行标准化配置，结构体包含8个关键成员：通信方向、主/从工作模式、数据宽度、时钟极性(CPOL)、时钟相位(CPHA)、NSS片选模式、波特率预分频系数、数据传输顺序。所有配置参数必须与外接SPI从机设备完全匹配，配置完成后必须调用SPI_Cmd函数使能SPI外设，才能启动硬件SPI通信功能。

  • 3.SPI通信的方向

SPI通信方向定义了数据的传输线路与工作方式，STM32 SPI外设支持3种通信方向模式，由主机统一控制时钟与通信时序：

  1. 2线全双工：拥有独立的MOSI（主机发送）和MISO（主机接收）引脚，发送与接收同步进行，通信效率最高，是OLED、Flash、传感器等设备的标准配置；
  2. 2线半双工：共用通信线路，同一时刻只能执行发送或接收操作，引脚占用少，适用于简单单向通信场景；
  3. 1线单工：仅使用单根数据线完成数据传输，分为只发送或只接收模式，硬件极简，工业开发中极少使用。
  • 4.数据宽度

数据宽度指SPI通信中单次移位传输的二进制数据位数，是数据格式的核心配置，STM32硬件SPI仅支持两种标准宽度：

  1. 8位数据宽度：最通用的工业标准，一次传输1字节数据，完美兼容OLED显示屏、SPI传感器、W25Q系列Flash、SD卡等所有常规SPI外设，是开发首选配置；
  2. 16位数据宽度：一次传输2字节数据，通信速度更快，仅适用于厂家定制的高速专用SPI设备，通用性极差。
    配置错误会导致数据传输错位、从机设备无法识别数据。
  • 5.时钟信号的极性和相位

时钟极性(CPOL)和时钟相位(CPHA)是SPI通信的核心时序参数，二者组合形成4种SPI工作模式，必须与从机设备完全一致，否则会出现通信失败、数据乱码、无响应等问题：

  • CPOL（时钟极性）：定义SPI总线空闲状态时，SCK时钟引脚的电平状态；CPOL=0空闲为低电平，CPOL=1空闲为高电平；
  • CPHA（时钟相位）：定义数据采样的时钟边沿；CPHA=0在第一个时钟边沿采样数据，CPHA=1在第二个时钟边沿采样数据；
  • 模式0（CPOL=0，CPHA=0）是最通用、最常用的标准模式，适配市面上99%的SPI从机设备。

1. TIM简介

TIM（Timer）定时器
-核心定义
定时器是对输入时钟进行计数的外设，并在计数值达到设定值时触发中断。

  • 基础结构与特性

  1. 时基单元

    • 包含：16位计数器、预分频器、自动重装寄存器
    • 核心能力：在 72MHz 计数时钟 下，最大可实现 59.65秒 的定时（由16位寄存器最大值决定：$2^{16}-1 = 65535$，计算时间约为 $65535/72MHz \approx 59.65s$）

  2. 功能拓展

    • 基础功能：定时中断
    • 高级功能：内外时钟源选择、输入捕获、输出比较、编码器接口、主从触发模式等

  3. 分类（按复杂度与应用场景）

    • 高级定时器
    • 通用定时器
    • 基本定时器

  • 核心知识点总结

  1. 引脚与通道对应
    PA2 = TIM2_CH3（定时器2通道3），因此必须使用 TIM_OC3Init 初始化。

  2. PWM频率计算
    公式：PWM频率 = 系统时钟 / [(PSC+1) × (ARR+1)]
    代入参数：72MHz ÷ (36 × 100) = 20000Hz = 20kHz。

  3. 占空比控制
    公式：占空比 = CCR值 / (ARR+1) × 100%
    示例：CCR=50 → 占空比50%；CCR=100 → 占空比100%。

  4. 关键函数作用

    • PWM_Init()：一次性配置好PWM的硬件、频率、初始状态；
    • PWM_SetCompare3()：运行时动态修改占空比，实现呼吸灯、调光、调速等效果。

  1. 硬件分工

    • PA4 / PA5：方向控制引脚，通过高低电平组合，控制电机正转/反转；
    • PA2：PWM调速引脚，通过修改占空比，控制电机转速快慢。

    速度参数 电机状态 PA4电平 PA5电平 PWM占空比
    50 正转，50%速 高 低 50
    -50 反转，50%速 低 高 50
    0 停止 高 低 0

  3. 关键知识点

    • 电机转速由 PWM占空比 决定：占空比越大，转速越快；
